## How computers work

- Reading `10` as ten. In binary `10` is 2, and in hex it is 16. Only the prefix or the context tells you the base. ([Binary and hexadecimal](../01-how-computers-work/01-bits-and-data/01-binary-and-hexadecimal.md))
- Mixing strings and numbers. `"FF"` is text and `0xFF` is the number 255; `"FF" == 255` is `False`. Convert text with `int("FF", 16)`, and turn a number into text with `hex()`, `bin()` or an f-string. ([Binary and hexadecimal](../01-how-computers-work/01-bits-and-data/01-binary-and-hexadecimal.md))
- Dropping leading zeros. The byte `0x0a` and the number `0xa` are the same value, but a hex dump or colour code needs both digits, so format with `:02x`. ([Binary and hexadecimal](../01-how-computers-work/01-bits-and-data/01-binary-and-hexadecimal.md))
- Mixing Mbps and MB/s. A 1 Gbps link moves at most 125 MB/s. A plan or a cloud limit quoted in bits looks eight times faster than the same number in bytes. ([Bits, bytes and units](../01-how-computers-work/01-bits-and-data/02-bits-bytes-and-units.md))
- Using 1,000 where memory uses 1,024, or the reverse, and calling the result exact. In code that computes sizes, pick one and name it in the variable (`size_kib`, `size_mb`). A mismatch of 7% at gigabyte scale is enough to fail a limit check. ([Bits, bytes and units](../01-how-computers-work/01-bits-and-data/02-bits-bytes-and-units.md))
- Confusing the number of values with the largest value. 8 bits hold 256 values, and the largest unsigned one is 255. ([Bits, bytes and units](../01-how-computers-work/01-bits-and-data/02-bits-bytes-and-units.md))
- Assuming Python's behaviour carries over. A calculation that is fine in Python can overflow in the same algorithm written in Java, or in a database column typed `integer`. ([Integers and two's complement](../01-how-computers-work/01-bits-and-data/03-integers-and-twos-complement.md))
- Using a 32-bit type for IDs, counts or timestamps that will grow. A signed 32-bit count of seconds since 1 January 1970 ends on 19 January 2038 at 03:14:07 UTC. Use 64 bits. ([Integers and two's complement](../01-how-computers-work/01-bits-and-data/03-integers-and-twos-complement.md))
- Mixing signed and unsigned in one comparison or subtraction. In C, `0u - 1` is a huge positive number, not $-1$. ([Integers and two's complement](../01-how-computers-work/01-bits-and-data/03-integers-and-twos-complement.md))
- `==` on computed floats. A test such as `assert total == 0.3` fails for some inputs. Use `math.isclose` or `pytest.approx`. ([Floating point](../01-how-computers-work/01-bits-and-data/04-floating-point.md))
- Storing money in a float or in a JSON number that a JavaScript client parses as a double. Send amounts as integer cents or as strings. ([Floating point](../01-how-computers-work/01-bits-and-data/04-floating-point.md))
- `Decimal(0.1)`. It faithfully copies the float's long tail. Write `Decimal("0.1")`. ([Floating point](../01-how-computers-work/01-bits-and-data/04-floating-point.md))
- Relying on the default encoding. Python's `open()` uses the system's default unless you give `encoding="utf-8"`, and on Windows that has been the locale's code page (cp1252 for most Western-language systems) rather than UTF-8. Python 3.15 changes the default to UTF-8 ([PEP 686](https://peps.python.org/pep-0686/), as of 2026), but code that must run on older versions should still name the encoding. ([Text, ASCII and Unicode](../01-how-computers-work/01-bits-and-data/05-text-ascii-and-unicode.md))
- Truncating by bytes. Cutting a UTF-8 byte string at a fixed length can split a multi-byte character: `"naïve".encode("utf-8")[:3]` ends in half of `ï` and decodes with an error or a replacement character. Cut the string, not the bytes. ([Text, ASCII and Unicode](../01-how-computers-work/01-bits-and-data/05-text-ascii-and-unicode.md))
- Assuming one character is one byte. A limit written in bytes (a database column, an HTTP header, a file format field) counts differently from a limit written in characters. ([Text, ASCII and Unicode](../01-how-computers-work/01-bits-and-data/05-text-ascii-and-unicode.md))
- Trusting file extensions or the `Content-Type` that came with an upload. The sender chooses both. Check the signature, and still treat the file as untrusted. ([Files, images and sound as bytes](../01-how-computers-work/01-bits-and-data/06-files-images-and-sound-as-bytes.md))
- Opening a binary file in text mode. In Python, `open("a.png")` decodes the bytes as text and can translate line endings, which corrupts the data. Use `open("a.png", "rb")`. ([Files, images and sound as bytes](../01-how-computers-work/01-bits-and-data/06-files-images-and-sound-as-bytes.md))
- Expecting a lossy file to survive repeated saving. Each JPEG re-save loses a little more detail. Keep the original, or use a lossless format for edited images. ([Files, images and sound as bytes](../01-how-computers-work/01-bits-and-data/06-files-images-and-sound-as-bytes.md))
- Thinking a bit is a number inside the chip. A bit is a voltage that circuits read as high or low. Memory and wires hold the voltages; the meaning of 1 and 0 as numbers, letters or colours comes from the layers above. ([Transistors and logic gates](../01-how-computers-work/02-hardware/01-transistors-and-logic-gates.md))
- Reading a gate as software. A gate has no steps. All its outputs follow its inputs continuously, and every gate in a circuit works at the same time. Code runs one step after another; hardware does not. ([Transistors and logic gates](../01-how-computers-work/02-hardware/01-transistors-and-logic-gates.md))
- Saying "the CPU adds one bit at a time". A ripple-carry adder is one circuit, and all its full adders work simultaneously. What is slow is waiting for the carry to settle, not stepping through bits. ([Boolean algebra and circuits](../01-how-computers-work/02-hardware/02-boolean-algebra-and-circuits.md))
- Mixing up RAM types. CPU caches are SRAM (fast, small). Main memory is DRAM (dense, refreshed). Neither keeps data without power. ([Boolean algebra and circuits](../01-how-computers-work/02-hardware/02-boolean-algebra-and-circuits.md))
- Comparing CPUs by GHz. A 5 GHz chip of one design can be slower than a 4 GHz chip of another. Compare benchmark results for a workload like yours. ([The CPU](../01-how-computers-work/02-hardware/03-the-cpu.md))
- Assuming more cores make a program faster. A single-threaded program does not change. Even a parallel program gains less than the core count, because of the serial parts and shared memory. ([The CPU](../01-how-computers-work/02-hardware/03-the-cpu.md))
- Counting logical CPUs as cores. `os.cpu_count()` reports logical CPUs, which on a chip with SMT is twice the physical cores. ([The CPU](../01-how-computers-work/02-hardware/03-the-cpu.md))
- Treating the table as exact. Use it to decide whether a design is plausible, then measure your own system. "This is in the milliseconds, not the nanoseconds" can come from the table; "this will take 3.2 ms" cannot. ([Memory hierarchy and latency numbers](../01-how-computers-work/02-hardware/04-memory-hierarchy-and-latency-numbers.md))
- Assuming a cache always helps. A Redis cache with a low hit rate adds a network round trip to every request and saves little. ([Memory hierarchy and latency numbers](../01-how-computers-work/02-hardware/04-memory-hierarchy-and-latency-numbers.md))
- Believing a "15,000 MB/s" drive makes every read fast. That is sequential throughput on large reads. A database doing one small random read at a time sees latency, about 100 µs even on a fast SSD. ([Storage, I/O and buses](../01-how-computers-work/02-hardware/05-storage-io-and-buses.md))
- Timing a file read twice and trusting the second number. The OS caches file contents in RAM, so the second read measures memory, not the disk. ([Storage, I/O and buses](../01-how-computers-work/02-hardware/05-storage-io-and-buses.md))
- Assuming a GPU speeds up any program. It helps with large, regular, data-parallel work. Small inputs, branchy code and code that moves data across PCIe constantly can run slower than on the CPU. ([GPUs and parallel hardware](../01-how-computers-work/02-hardware/06-gpus-and-parallel-hardware.md))
- Comparing a GPU's thousands of cores with a CPU's dozen. They do different amounts of work per core. Compare time on the actual task. ([GPUs and parallel hardware](../01-how-computers-work/02-hardware/06-gpus-and-parallel-hardware.md))
- Treating "fits in VRAM" as "weights fit". Context length, batch size and the framework add memory on top of the weights. ([GPUs and parallel hardware](../01-how-computers-work/02-hardware/06-gpus-and-parallel-hardware.md))
- Reading the operands backwards. `mov eax, ebx` copies `ebx` into `eax` in Intel syntax, but `movl %eax, %ebx` copies `eax` into `ebx` in AT&T syntax. Pass `-masm=intel` to GCC or Clang to get Intel. ([Machine code and assembly](../01-how-computers-work/03-code-to-running-program/01-machine-code-and-assembly.md))
- Expecting assembly to be portable. The same C function gives different assembly on ARM64, and on Windows x86-64 the arguments arrive in `rcx` and `rdx`. A listing is only meaningful with its ISA and operating system. ([Machine code and assembly](../01-how-computers-work/03-code-to-running-program/01-machine-code-and-assembly.md))
- Judging speed from a `-O0` build. Unoptimized code is often several times slower than what you ship. ([Machine code and assembly](../01-how-computers-work/03-code-to-running-program/01-machine-code-and-assembly.md))
- Saying "Python is interpreted, so there is no compile step". CPython compiles every module to bytecode first; a `SyntaxError` is raised at that step, before any line runs. ([Compilers, interpreters and JIT](../01-how-computers-work/03-code-to-running-program/02-compilers-interpreters-and-jit.md))
- Timing a JIT language with one cold run or an unused result. The first calls run in the interpreter, and an optimizer may delete a computation whose result nobody reads. Run the code several times and use the result. ([Compilers, interpreters and JIT](../01-how-computers-work/03-code-to-running-program/02-compilers-interpreters-and-jit.md))
- Assuming `node file.ts` checks types. It strips them and runs, so `total("4", 3)` prints 12 with no error. Run `tsc --noEmit` (in CI too) to get the type errors. ([Compilers, interpreters and JIT](../01-how-computers-work/03-code-to-running-program/02-compilers-interpreters-and-jit.md))

## Operating systems and Linux

- Saying "Linux" when you mean a distribution. "It works on Linux" is a weak claim, because Ubuntu and Alpine ship different C libraries and different package tools. Name the distribution and its version in bug reports and prompts. ([What an OS and kernel do](../02-operating-systems-and-linux/01-os-concepts/01-what-an-os-and-kernel-do.md))
- Assuming user-space tools are the OS. `bash`, `ls` and `python` run in user space like any other program. They ask the kernel for work. ([What an OS and kernel do](../02-operating-systems-and-linux/01-os-concepts/01-what-an-os-and-kernel-do.md))
- Using threads for CPU-bound Python and expecting a speed-up. Use processes (`multiprocessing`, `ProcessPoolExecutor`), or move the hot loop into native code such as NumPy. ([Processes, threads and scheduling](../02-operating-systems-and-linux/01-os-concepts/02-processes-threads-and-scheduling.md))
- On Windows and macOS, `multiprocessing` starts a fresh interpreter that imports your file again. Without `if __name__ == "__main__":` around the start-up code, it can launch processes forever or raise a `RuntimeError`. ([Processes, threads and scheduling](../02-operating-systems-and-linux/01-os-concepts/02-processes-threads-and-scheduling.md))
- Confusing a PID with a thread. A PID names a process, and the kernel can reuse it after the process exits. Never store one as a permanent identifier. ([Processes, threads and scheduling](../02-operating-systems-and-linux/01-os-concepts/02-processes-threads-and-scheduling.md))
- Reading "free memory" from `free -h` or Task Manager and panicking. Linux fills spare RAM with cache. The `available` column is the number to read. ([Memory and virtual memory](../02-operating-systems-and-linux/01-os-concepts/03-memory-and-virtual-memory.md))
- Blaming only your program for an OOM kill. A container can have a [lower memory limit](../13-devops-and-cloud/01-containers/01-vms-vs-containers.md) than the machine, so a process can die on a half-empty host. The kernel log shows who was killed and why. ([Memory and virtual memory](../02-operating-systems-and-linux/01-os-concepts/03-memory-and-virtual-memory.md))
- Raising the recursion limit to "fix" a `RecursionError`. A bigger limit can overflow the real stack and crash the interpreter. Rewrite the recursion as a loop. ([Memory and virtual memory](../02-operating-systems-and-linux/01-os-concepts/03-memory-and-virtual-memory.md))
- Thinking `rm` erases a file. It removes one name and lowers the link count. The data is freed when no name and no open file remains. The same fact explains why a deleted log file can keep eating disk space while a process still holds it open. ([File systems](../02-operating-systems-and-linux/01-os-concepts/04-file-systems.md))
- Using a hard link where you need a soft link. Hard links cannot point to directories, and cannot cross file systems, because inode numbers are only unique inside one file system. Use a soft link for those. ([File systems](../02-operating-systems-and-linux/01-os-concepts/04-file-systems.md))
- Relative soft links. `ln -s../data/file.txt link` stores that text, which is resolved from the link's own folder. Moving the link breaks it. ([File systems](../02-operating-systems-and-linux/01-os-concepts/04-file-systems.md))
- Assuming slow I/O code is slow because of the language. Many tiny reads and writes mean many system calls. Batch them with buffering or larger reads. ([System calls and kernel mode](../02-operating-systems-and-linux/01-os-concepts/05-system-calls-and-kernel-mode.md))
- Pasting a trace publicly. It shows file paths, arguments and sometimes secrets such as tokens. ([System calls and kernel mode](../02-operating-systems-and-linux/01-os-concepts/05-system-calls-and-kernel-mode.md))
- Reading `strace -c` output as the program's whole run time. It shows time inside system calls, not time spent computing in user space. ([System calls and kernel mode](../02-operating-systems-and-linux/01-os-concepts/05-system-calls-and-kernel-mode.md))
- Forgetting quotes around a variable that holds a file name. `rm $file` with `file="my report.txt"` removes two files named `my` and `report.txt`. Write `rm "$file"`. ([Shell and terminal basics](../02-operating-systems-and-linux/02-linux-command-line/01-shell-and-terminal-basics.md))
- Reading `$?` late. It holds the exit code of the most recent command only, so `echo hi; echo $?` prints 0 even if an earlier command failed. Save it (`code=$?`) right away if you need it. ([Shell and terminal basics](../02-operating-systems-and-linux/02-linux-command-line/01-shell-and-terminal-basics.md))
- Pasting a command from the web with a trailing `sudo` or `rm` you do not understand. Read it, and run `man` or `--help` on each part first. ([Shell and terminal basics](../02-operating-systems-and-linux/02-linux-command-line/01-shell-and-terminal-basics.md))
- `rm -rf` with a variable or a space in the wrong place. `rm -rf $DIR/` with an empty `DIR` becomes `rm -rf /`, and `rm -rf ~ /tmp/x` (a stray space) deletes your whole home. Run `ls` on the exact path first, keep the `-f` off unless you need it, and quote variables. ([Files and navigation](../02-operating-systems-and-linux/02-linux-command-line/02-files-and-navigation.md))
- `mv a b` overwrites `b` silently if it exists, and `cp` does too. Use `-i`, or `-n` to never overwrite. ([Files and navigation](../02-operating-systems-and-linux/02-linux-command-line/02-files-and-navigation.md))
- Working in `/mnt/c` for Linux projects. Everything works but file operations are slow, and permissions and line endings behave oddly. Use `~/projects`. ([Files and navigation](../02-operating-systems-and-linux/02-linux-command-line/02-files-and-navigation.md))
- `chmod 777` lets every user and program on the machine write and run the file. It hides the real problem (wrong owner, wrong group, or a missing bit on a parent directory) and lets any compromised process overwrite the file. Find which class applies and add the one bit that is missing. ([Users, groups and permissions](../02-operating-systems-and-linux/02-linux-command-line/03-users-groups-and-permissions.md))
- A wrong path in `chmod -R` or `chown -R` can change thousands of files, and a recursive `chmod 644` strips `x` from directories, which locks you out of them. Run `ls -ld` on the target first. ([Users, groups and permissions](../02-operating-systems-and-linux/02-linux-command-line/03-users-groups-and-permissions.md))
- `usermod -G devteam bob` without `-a` replaces all of bob's supplementary groups. Use `usermod -aG`. Group changes also apply only to new login sessions. ([Users, groups and permissions](../02-operating-systems-and-linux/02-linux-command-line/03-users-groups-and-permissions.md))
- `sort file > file`. The shell empties the file before `sort` reads it, so you lose the data. Write to a different file, then move it back. ([Pipes, redirection and text tools](../02-operating-systems-and-linux/02-linux-command-line/04-pipes-redirection-and-text-tools.md))
- `uniq -c` without `sort` first. It only collapses neighbours, so the counts come out wrong without an error. ([Pipes, redirection and text tools](../02-operating-systems-and-linux/02-linux-command-line/04-pipes-redirection-and-text-tools.md))
- `>` instead of `>>`. A single `>` replaces the file every time. Use `>>` for logs. ([Pipes, redirection and text tools](../02-operating-systems-and-linux/02-linux-command-line/04-pipes-redirection-and-text-tools.md))
- Reaching for `kill -9` first. The process cannot close files or release locks, which can leave a corrupt file or a lock that blocks the next start. Send plain `kill`, wait, then escalate. ([Processes and signals](../02-operating-systems-and-linux/02-linux-command-line/05-processes-and-signals.md))
- Killing by name with `pkill` or `killall` on a shared machine. It matches every process with that name, including other people's. Find the PID with `ps` and kill that one. ([Processes and signals](../02-operating-systems-and-linux/02-linux-command-line/05-processes-and-signals.md))
- Expecting a `&` job to survive closing the terminal. Use `nohup`, `tmux` or a service. ([Processes and signals](../02-operating-systems-and-linux/02-linux-command-line/05-processes-and-signals.md))
- Running `apt install` without `apt update` first on a fresh machine, then reading "Unable to locate package" as "the package does not exist". ([Packages with apt](../02-operating-systems-and-linux/02-linux-command-line/06-packages-with-apt.md))
- `sudo apt install` with `-y` on a package name you typed from memory. A typo can pull in a different package. Read the list APT prints before you answer yes. ([Packages with apt](../02-operating-systems-and-linux/02-linux-command-line/06-packages-with-apt.md))
- Pasting a "one-line install" from a blog that adds a repository key and source, then running `apt upgrade`. You have just given that site root on your machine. Use the vendor's documentation. ([Packages with apt](../02-operating-systems-and-linux/02-linux-command-line/06-packages-with-apt.md))
- Editing a unit file and forgetting `sudo systemctl daemon-reload`. systemd keeps using the old copy, and `status` warns that the unit changed on disk. ([Services, systemd and logs](../02-operating-systems-and-linux/02-linux-command-line/07-services-systemd-and-logs.md))
- A relative or bare command in `ExecStart=` (`python app.py`). Use the full path, found with `which python3`. ([Services, systemd and logs](../02-operating-systems-and-linux/02-linux-command-line/07-services-systemd-and-logs.md))
- Running the service as root because it is easier. A bug in the app then has root. Make a dedicated user and give it only the folder it needs. ([Services, systemd and logs](../02-operating-systems-and-linux/02-linux-command-line/07-services-systemd-and-logs.md))
- `PATH=$HOME/bin` instead of `PATH=$HOME/bin:$PATH`. It replaces the list, and nothing else is found until you open a new shell. ([Environment variables and path](../02-operating-systems-and-linux/02-linux-command-line/08-environment-variables-and-path.md))
- Editing `~/.bashrc` and expecting the open terminal to change. Run `source ~/.bashrc`. ([Environment variables and path](../02-operating-systems-and-linux/02-linux-command-line/08-environment-variables-and-path.md))
- A variable assigned without `export`. It works in your shell and is empty inside the script or program. ([Environment variables and path](../02-operating-systems-and-linux/02-linux-command-line/08-environment-variables-and-path.md))
- A script that works in your terminal and fails in cron. Cause: the short `PATH`, a relative path, or a missing environment variable. Use full paths and log the output. ([Shell scripting and cron](../02-operating-systems-and-linux/02-linux-command-line/09-shell-scripting-and-cron.md))
- `rm -rf "$dir/"*` where `dir` can be empty. With `set -u` an unset `dir` stops the script, but an empty string does not; check `[ -n "$dir" ]` first. ([Shell scripting and cron](../02-operating-systems-and-linux/02-linux-command-line/09-shell-scripting-and-cron.md))
- Spaces in the assignment (`name = "Ada"`). Bash runs a command named `name`. ([Shell scripting and cron](../02-operating-systems-and-linux/02-linux-command-line/09-shell-scripting-and-cron.md))
- Sharing or committing the wrong file. Only `*.pub` is shareable. A private key in a Git repository must be treated as stolen: remove it, create a new pair and replace it everywhere. ([SSH and keys](../02-operating-systems-and-linux/02-linux-command-line/10-ssh-and-keys.md))
- Pressing `yes` or deleting `known_hosts` entries to silence a changed-host-key warning without asking why. ([SSH and keys](../02-operating-systems-and-linux/02-linux-command-line/10-ssh-and-keys.md))
- A key with no passphrase on a laptop you carry. Use a passphrase and the agent. ([SSH and keys](../02-operating-systems-and-linux/02-linux-command-line/10-ssh-and-keys.md))

## Programming fundamentals

- Using `is` to compare values. `n is m` above is `False` for equal integers. Use `==`, and reserve `is` for `None`. ([Values, types and variables](../03-programming-fundamentals/01-python-basics/01-values-types-and-variables.md))
- `//` on negatives. `-7 // 2` is `-4`, not `-3`. If you port code from C, Java or JavaScript, `int(-7 / 2)` gives the truncating answer. ([Values, types and variables](../03-programming-fundamentals/01-python-basics/01-values-types-and-variables.md))
- Assuming `/` returns an int when both operands are ints. In Python 2 it did; in Python 3 it returns a float, which then breaks list indexing with `TypeError`. Use `//`. ([Values, types and variables](../03-programming-fundamentals/01-python-basics/01-values-types-and-variables.md))
- Changing a list while looping over it. The loop index keeps advancing, so items get skipped. ([Control flow](../03-programming-fundamentals/01-python-basics/02-control-flow.md))
- `if x:` when `0` or an empty string is valid input. Use `is None` for "missing". ([Control flow](../03-programming-fundamentals/01-python-basics/02-control-flow.md))
- A name in a `case` is a capture. `case RED:` matches anything and rebinds `RED`. To match a constant, use a dotted name such as `Colour.RED` or a literal. ([Control flow](../03-programming-fundamentals/01-python-basics/02-control-flow.md))
- Any mutable default (`[]`, `{}`, `set()`, an object) is shared between calls. Use `None`. Dataclasses reject a list default with a `ValueError`; the fix there is `field(default_factory=list)`. ([Functions and scope](../03-programming-fundamentals/01-python-basics/03-functions-and-scope.md))
- Forgetting `return`. A function ending in `x + 1` computes the value and throws it away, and the caller gets `None`. ([Functions and scope](../03-programming-fundamentals/01-python-basics/03-functions-and-scope.md))
- Shadowing built-ins by naming a variable `list`, `id`, `input` or `max`. The next call to the built-in then fails with a confusing `TypeError`. ([Functions and scope](../03-programming-fundamentals/01-python-basics/03-functions-and-scope.md))
- `[[0] * 3] * 3` makes three references to one inner list. Use a comprehension for a grid. ([Lists, dicts, sets and tuples](../03-programming-fundamentals/01-python-basics/04-lists-dicts-sets-and-tuples.md))
- Testing membership in a list inside a loop. `x in some_list` scans the list on each pass, so the loop is $O(n^2)$. Build a `set` once. ([Lists, dicts, sets and tuples](../03-programming-fundamentals/01-python-basics/04-lists-dicts-sets-and-tuples.md))
- Using a list as a dict key or set member raises `TypeError: unhashable type`. Convert it to a tuple. ([Lists, dicts, sets and tuples](../03-programming-fundamentals/01-python-basics/04-lists-dicts-sets-and-tuples.md))
- Building a large string with `s += piece` in a loop. CPython has an optimization that makes it fast for a local variable, but it fails for an attribute or list item, and other implementations lack it. In a quick test with 100,000 pieces, `s += p` on a local took 0.007 s, the same on a list item took 0.49 s, and `"".join(parts)` took 0.0007 s. Collect pieces in a list and call `"".join(...)`. ([Strings and formatting](../03-programming-fundamentals/01-python-basics/05-strings-and-formatting.md))
- A Windows path in a normal string. `"C:\new\table"` contains a newline and a tab. Use a raw string, forward slashes, or `pathlib`. ([Strings and formatting](../03-programming-fundamentals/01-python-basics/05-strings-and-formatting.md))
- Assuming `len(s)` counts what users see. It counts code points. `"caf\u00e9"` (one code point for the accent) and `"cafe\u0301"` (letter plus combining accent) look identical, have lengths 4 and 5, and compare unequal. Normalize with `unicodedata.normalize("NFC", s)`, and use `casefold()` for case-insensitive comparison: `"Stra\u00dfe".casefold() == "STRASSE".casefold()` is `True`. ([Strings and formatting](../03-programming-fundamentals/01-python-basics/05-strings-and-formatting.md))
- `except:` or `except Exception: pass`. It hides bugs, and a bare `except:` also catches Ctrl-C. Catch the specific class, and log or re-raise anything you do not handle. ([Errors and exceptions](../03-programming-fundamentals/01-python-basics/06-errors-and-exceptions.md))
- `assert` for input validation. Assertions are removed when Python runs with `-O`. In the test below, the same call raises `AssertionError` normally and returns a wrong balance with `-O`. ([Errors and exceptions](../03-programming-fundamentals/01-python-basics/06-errors-and-exceptions.md))
- `return` inside `finally` replaces the result or exception from `try`. Don't put it there. ([Errors and exceptions](../03-programming-fundamentals/01-python-basics/06-errors-and-exceptions.md))
- `open(path)` with no `encoding`. The bug appears only on another machine, or when a non-ASCII character first shows up. Always write `encoding="utf-8"` for text. ([Files and I/O](../03-programming-fundamentals/01-python-basics/07-files-and-io.md))
- Opening a file with `"w"` to check whether it exists or to append. `"w"` truncates immediately. Use `"a"` to add, `"x"` to create safely, or `Path.exists()`. ([Files and I/O](../03-programming-fundamentals/01-python-basics/07-files-and-io.md))
- Building paths by string concatenation, as in `"data\\" + name`. Use `Path("data") / name`, which works on Windows, Linux and macOS. ([Files and I/O](../03-programming-fundamentals/01-python-basics/07-files-and-io.md))
- Installing into the global Python. Packages from different projects mix, and later you cannot tell what a project needs. If the prompt does not show `(.venv)` and you did not use `.venv/Scripts/python`, you are probably installing globally. ([Modules, packages, pip and venv](../03-programming-fundamentals/01-python-basics/08-modules-packages-pip-and-venv.md))
- Running `python shop/cli.py` for code that uses relative imports, or naming a file after a standard library module. Run `python -m shop.cli` from the project root, and rename the file. ([Modules, packages, pip and venv](../03-programming-fundamentals/01-python-basics/08-modules-packages-pip-and-venv.md))
- An unpinned `requirements.txt` (`requests` with no version). A new release can break the build next month. Pin with `==`, or with a lock file from your tool. ([Modules, packages, pip and venv](../03-programming-fundamentals/01-python-basics/08-modules-packages-pip-and-venv.md))
- A base case that is never reached, such as `factorial(-1)` with the check `n == 0`. The argument goes `-2`, `-3`, and so on until `RecursionError`. Check that every call moves toward the base case, or reject bad input first. ([Recursion](../03-programming-fundamentals/02-thinking-like-a-programmer/01-recursion.md))
- Raising the recursion limit to hide a deep recursion. If depth grows with the input size, rewrite it as a loop or use an explicit stack. ([Recursion](../03-programming-fundamentals/02-thinking-like-a-programmer/01-recursion.md))
- `b = a` to "save a copy" before changing `a`. Both names see the change. Use `a.copy()` or `copy.deepcopy(a)`. ([References, mutability and copying](../03-programming-fundamentals/02-thinking-like-a-programmer/02-references-mutability-and-copying.md))
- Assuming `copy()` is deep for nested data. If the data contains lists or dicts, mutate one and check the copy; if it changes, you needed `deepcopy`. ([References, mutability and copying](../03-programming-fundamentals/02-thinking-like-a-programmer/02-references-mutability-and-copying.md))
- A function that mutates its argument without saying so. Either document it, or return a new object and leave the argument alone. ([References, mutability and copying](../03-programming-fundamentals/02-thinking-like-a-programmer/02-references-mutability-and-copying.md))
- Believing hints are enforced. Python ignores them at run time, so `area("3", 4)` runs. Run a checker in your editor or CI to get any benefit. ([Type systems](../03-programming-fundamentals/02-thinking-like-a-programmer/03-type-systems.md))
- Calling Python "weakly typed" because variables have no declared type. Python refuses `1 + "1"`, so it is dynamic and strong. JavaScript is dynamic and weak. ([Type systems](../03-programming-fundamentals/02-thinking-like-a-programmer/03-type-systems.md))
- Silencing a checker with `Any` or `# type: ignore` everywhere. Each one turns checking off for that value, and errors move back to run time. ([Type systems](../03-programming-fundamentals/02-thinking-like-a-programmer/03-type-systems.md))
- Changing code before you can reproduce the bug. You cannot tell whether a change fixed it, and you may fix a different bug. ([Reading code and debugging](../03-programming-fundamentals/02-thinking-like-a-programmer/04-reading-code-and-debugging.md))
- Changing several things at once. If the bug disappears you do not know which change did it, and you may have added new ones. Change one thing, then rerun. ([Reading code and debugging](../03-programming-fundamentals/02-thinking-like-a-programmer/04-reading-code-and-debugging.md))
- Assuming the library is wrong. Check your inputs and your call first; library bugs are rare compared to wrong arguments. ([Reading code and debugging](../03-programming-fundamentals/02-thinking-like-a-programmer/04-reading-code-and-debugging.md))
- A mutable class attribute (a list, dict or set) is shared by every object. Put per-object state in `__init__`. Use class attributes for constants and defaults that never change in place. ([Classes and objects](../03-programming-fundamentals/03-oop-and-paradigms/01-classes-and-objects.md))
- Forgetting `self` in the method definition. `def deposit(amount)` fails with `TypeError: Account.deposit() takes 1 positional argument but 2 were given`, because Python passed the object as the first argument. ([Classes and objects](../03-programming-fundamentals/03-oop-and-paradigms/01-classes-and-objects.md))
- Assigning to an attribute you meant to read. `a.bank = "Other"` does not change the bank for everyone; it creates an instance attribute on `a` that hides the class one. Write `Account.bank = "Other"` to change the shared value. ([Classes and objects](../03-programming-fundamentals/03-oop-and-paradigms/01-classes-and-objects.md))
- A subclass `__init__` that skips `super().__init__(...)`. The parent's attributes are never set, and the failure comes later: `AttributeError: 'Savings' object has no attribute 'owner'`. ([Encapsulation, inheritance and polymorphism](../03-programming-fundamentals/03-oop-and-paradigms/02-encapsulation-inheritance-and-polymorphism.md))
- Inheriting only to reuse code. Inheritance says "is a", and every subclass must work wherever its parent is expected. A subclass that removes or changes what the parent promises breaks callers. If the relationship is "has a" or "uses", use composition, covered in the next lesson. ([Encapsulation, inheritance and polymorphism](../03-programming-fundamentals/03-oop-and-paradigms/02-encapsulation-inheritance-and-polymorphism.md))
- Deep or multiple inheritance. With two parents, the MRO decides which `super()` runs next, and the result is hard to predict (a `D(B, C)` calls `B`, then `C`, then `A`). Prefer one parent, and one or two levels. ([Encapsulation, inheritance and polymorphism](../03-programming-fundamentals/03-oop-and-paradigms/02-encapsulation-inheritance-and-polymorphism.md))
- Inheriting from a class just to borrow one method. `class Car(Engine)` makes every `Car` an `Engine` and exposes all of the engine's methods. Give `Car` an `engine` attribute and call `self.engine.start()`. ([Composition and interfaces](../03-programming-fundamentals/03-oop-and-paradigms/03-composition-and-interfaces.md))
- Expecting a Protocol to be checked when the program runs. Python only checks it when you run mypy or pyright. If you need an error at runtime, use an ABC. ([Composition and interfaces](../03-programming-fundamentals/03-oop-and-paradigms/03-composition-and-interfaces.md))
- Creating the dependency inside the class (`self.notifier = EmailNotifier()` in `__init__`). That hard-wires the class to one choice and makes tests send real emails. Take it as a parameter. ([Composition and interfaces](../03-programming-fundamentals/03-oop-and-paradigms/03-composition-and-interfaces.md))
- `nums.sort()` sorts in place and returns `None`, so `result = nums.sort()` leaves `result` as `None`. Use `sorted(nums)` for a new list. The same split exists in JavaScript: `arr.sort()` and `arr.reverse()` mutate, `arr.map()` does not. ([Functional programming ideas](../03-programming-fundamentals/03-oop-and-paradigms/04-functional-programming-ideas.md))
- A closure captures a variable, not its value. `[lambda: i for i in range(3)]` creates three functions that all return 2, because they share one `i`. Bind the current value with a default argument: `lambda i=i: i`. ([Functional programming ideas](../03-programming-fundamentals/03-oop-and-paradigms/04-functional-programming-ideas.md))
- Nesting `map`, `filter` and `lambda` until nobody can read it. If a comprehension with a name for each step is clearer, use that. Pure functions are a tool, not a goal; a counter or a cache is fine when it is hidden behind a small interface. ([Functional programming ideas](../03-programming-fundamentals/03-oop-and-paradigms/04-functional-programming-ideas.md))

## Developer tools and workflow

- Installing the Python extension on the Windows side while your code runs in WSL. The language server then analyses a different Python than the one that runs your code. Open the folder through WSL and install the extension there (the Extensions view shows an Install button for WSL). ([VS Code and IDEs](../04-developer-tools-and-workflow/01-editor-and-git/01-vs-code-and-ides.md))
- Trusting every squiggle or every "quick fix". A server with the wrong interpreter reports errors for packages you did install. Check the interpreter shown in the status bar first. ([VS Code and IDEs](../04-developer-tools-and-workflow/01-editor-and-git/01-vs-code-and-ides.md))
- Installing many extensions. Each runs code with access to your files. Install extensions from known publishers and remove ones you do not use. ([VS Code and IDEs](../04-developer-tools-and-workflow/01-editor-and-git/01-vs-code-and-ides.md))
- `git add.` stages everything, including files you did not mean to commit. Run `git status` before every commit, and read `git diff --staged`. ([Git basics](../04-developer-tools-and-workflow/01-editor-and-git/02-git-basics.md))
- `git restore <file>` discards edits permanently, because they were never committed. If you are unsure, commit first or use stash (next lesson). ([Git basics](../04-developer-tools-and-workflow/01-editor-and-git/02-git-basics.md))
- Committing a secret and then deleting it in the next commit. It remains in history. Treat the secret as leaked and rotate it. ([Git basics](../04-developer-tools-and-workflow/01-editor-and-git/02-git-basics.md))
- Committing a file that still contains `<<<<<<<` markers. Search for them (`grep -rn '<<<<<<<'.`) before `git add`. ([Branches, merging and conflicts](../04-developer-tools-and-workflow/01-editor-and-git/03-branches-merging-and-conflicts.md))
- `git reset --hard` and `git push --force` on a shared branch. They discard or overwrite other people's work. Use `git revert`, or `--force-with-lease` on your own feature branch only. ([Branches, merging and conflicts](../04-developer-tools-and-workflow/01-editor-and-git/03-branches-merging-and-conflicts.md))
- Switching branches with uncommitted edits. Git refuses if they would be overwritten; commit or stash first. ([Branches, merging and conflicts](../04-developer-tools-and-workflow/01-editor-and-git/03-branches-merging-and-conflicts.md))
- Forcing a rejected push with `git push --force`. It overwrites the remote's commits. Pull first. If you rebased your own branch and must force, use `git push --force-with-lease`, which refuses if someone else pushed. ([GitHub, pull requests and code review](../04-developer-tools-and-workflow/01-editor-and-git/04-github-pull-requests-and-code-review.md))
- Committing straight to `main` and opening a PR from a branch that started long ago. Create a branch per change and update it from `main` often so the PR stays small. ([GitHub, pull requests and code review](../04-developer-tools-and-workflow/01-editor-and-git/04-github-pull-requests-and-code-review.md))
- Pasting a personal access token into a remote URL or a commit. Tokens in history count as leaked; revoke them and make a new one. ([GitHub, pull requests and code review](../04-developer-tools-and-workflow/01-editor-and-git/04-github-pull-requests-and-code-review.md))
- Deleting the lockfile to "fix" an install problem. The next install resolves the ranges again and may pick different versions, so a build that worked yesterday can break. Fix the actual conflict and keep the lockfile. ([Package managers and dependencies](../04-developer-tools-and-workflow/02-project-plumbing/01-package-managers-and-dependencies.md))
- Committing `node_modules` or `.venv`. They are large, machine-specific and rebuilt from the lockfile. Put them in `.gitignore`. ([Package managers and dependencies](../04-developer-tools-and-workflow/02-project-plumbing/01-package-managers-and-dependencies.md))
- Running `npm install` in a build pipeline. It can rewrite the lockfile and install something you did not review. Use `npm ci`. ([Package managers and dependencies](../04-developer-tools-and-workflow/02-project-plumbing/01-package-managers-and-dependencies.md))
- Committing `.env` "just this once". The commit stays in history even after you delete the file. Add `.env` to `.gitignore` first; `git check-ignore -v.env` confirms the rule is working. ([Config, environment variables and secrets](../04-developer-tools-and-workflow/02-project-plumbing/02-config-env-vars-and-secrets.md))
- Reading `DEBUG=false` as a boolean. Environment variables are strings, so `if os.environ["DEBUG"]:` is true for `"false"`. Compare the text. ([Config, environment variables and secrets](../04-developer-tools-and-workflow/02-project-plumbing/02-config-env-vars-and-secrets.md))
- Putting an API key in browser JavaScript, including variables that a bundler copies into the front-end build. Anything shipped to the browser is public. Keep the key on a server and have the browser call your server. ([Config, environment variables and secrets](../04-developer-tools-and-workflow/02-project-plumbing/02-config-env-vars-and-secrets.md))
- Building CSV or JSON by string concatenation. A name such as `O"Brien, Jr.` breaks the CSV, and a quote in a JSON string breaks the JSON. Use the `csv` and `json` libraries to write as well as read. ([Data formats: JSON, YAML and CSV](../04-developer-tools-and-workflow/02-project-plumbing/03-data-formats-json-yaml-csv.md))
- Assuming a YAML value is the type it looks like. Quote anything ambiguous (`"NO"`, `"01234"`, `"1.10"`), and print the parsed result once. ([Data formats: JSON, YAML and CSV](../04-developer-tools-and-workflow/02-project-plumbing/03-data-formats-json-yaml-csv.md))
- Opening a CSV with the default encoding. Pass `encoding="utf-8"` (or `utf-8-sig` for Excel files) explicitly, as the Python files lesson advises. ([Data formats: JSON, YAML and CSV](../04-developer-tools-and-workflow/02-project-plumbing/03-data-formats-json-yaml-csv.md))
- An unescaped dot. `1.5` as a pattern also matches `105`. Write `1\.5`. ([Regular expressions](../04-developer-tools-and-workflow/02-project-plumbing/04-regular-expressions.md))
- Using `match` or `test` when you need the whole string to fit. In Python, `re.search(r"\d+", "123abc")` succeeds; `re.fullmatch` returns `None`. Anchor with `^...$` (JavaScript) or use `fullmatch`. ([Regular expressions](../04-developer-tools-and-workflow/02-project-plumbing/04-regular-expressions.md))
- Using greedy `.*` between two markers, which swallows everything up to the last marker. Use `.*?` or a negated class such as `[^<]*`. ([Regular expressions](../04-developer-tools-and-workflow/02-project-plumbing/04-regular-expressions.md))
- A test that cannot fail. If you only run the code and never assert (or assert something always true), it passes whatever the code does. Break the code on purpose once and confirm the test goes red. ([Unit testing](../04-developer-tools-and-workflow/03-code-quality/01-unit-testing.md))
- Testing the implementation. A test that checks which helper was called breaks when you refactor, even though the behaviour is right. Assert on results. ([Unit testing](../04-developer-tools-and-workflow/03-code-quality/01-unit-testing.md))
- Tests that depend on each other or on order. Each test should arrange its own data, which is what fixtures are for. ([Unit testing](../04-developer-tools-and-workflow/03-code-quality/01-unit-testing.md))
- Mocking so much that the test checks only the mock. If every dependency is a double and the assertion is `assert_called_once`, a wrong formula still passes. Assert on results, and add one integration test with the real parts. ([Integration tests, mocks and end-to-end tests](../04-developer-tools-and-workflow/03-code-quality/02-integration-tests-mocks-and-e2e.md))
- A mock that disagrees with reality. The real API may return `{"rates": {"CAD": 1.25}}` while your mock returns `{"rate": 1.25}`. Copy a real response into the test, and keep one e2e or integration check against the real service. ([Integration tests, mocks and end-to-end tests](../04-developer-tools-and-workflow/03-code-quality/02-integration-tests-mocks-and-e2e.md))
- Fixing a flaky test by adding `sleep` or by re-running it. Find the cause: a real clock, shared data between tests, random values, or waiting for a fixed time instead of for a condition. ([Integration tests, mocks and end-to-end tests](../04-developer-tools-and-workflow/03-code-quality/02-integration-tests-mocks-and-e2e.md))
- Silencing the tool instead of reading it. A `# type: ignore` or `# noqa` hides one warning, and a pile of them hides the real problem. Add one only with a comment saying why. ([Linters, formatters and type checkers](../04-developer-tools-and-workflow/03-code-quality/03-linters-formatters-and-type-checkers.md))
- Different tool versions or settings on each machine. The editor formats one way and CI checks another. Keep the config in the repository (`pyproject.toml`, `eslint.config.mjs`, `.prettierrc`) and pin versions. ([Linters, formatters and type checkers](../04-developer-tools-and-workflow/03-code-quality/03-linters-formatters-and-type-checkers.md))
- Believing that passing types means correct code. Python annotations are not checked at runtime, and a type checker cannot see a wrong formula. Tests still matter. ([Linters, formatters and type checkers](../04-developer-tools-and-workflow/03-code-quality/03-linters-formatters-and-type-checkers.md))
- Documentation that is out of date. A wrong README is worse than none. Keep commands in files that get run (a `Makefile`, scripts, CI) and have the README point to them, and review docs in the same pull request as the code. ([Documentation and readmes](../04-developer-tools-and-workflow/03-code-quality/04-documentation-and-readmes.md))
- Comments that restate the code, or commented-out code. Version control remembers old code; delete it. ([Documentation and readmes](../04-developer-tools-and-workflow/03-code-quality/04-documentation-and-readmes.md))
- An agent file that grows into a manual. Long files bury the rules. Keep it to commands, non-obvious rules and pointers to other docs. ([Documentation and readmes](../04-developer-tools-and-workflow/03-code-quality/04-documentation-and-readmes.md))
- Forgetting `$` on a constant such as a tax rate. The copied formula points at an empty cell and silently multiplies by 0. Check one copied formula by clicking it, not just the first one. ([Excel formulas and references](../04-developer-tools-and-workflow/04-spreadsheets/01-excel-formulas-and-references.md))
- Whole-number looking values that are text. `SUM` ignores text cells, so a column of numbers pasted from a CSV can sum to less than it should. Left-aligned numbers are the clue. ([Excel formulas and references](../04-developer-tools-and-workflow/04-spreadsheets/01-excel-formulas-and-references.md))
- Hiding errors with `IFERROR` everywhere. It also hides a real `#REF!`. Wrap only the cell where an error is expected. ([Excel formulas and references](../04-developer-tools-and-workflow/04-spreadsheets/01-excel-formulas-and-references.md))
- A lookup key that looks equal but isn't, such as `"East "` with a trailing space or a number `101` against the text `"101"`. The result is `#N/A`. Wrap the key in `TRIM`, or fix the types. ([Lookups, pivot tables and charts](../04-developer-tools-and-workflow/04-spreadsheets/02-lookups-pivot-tables-and-charts.md))
- A pivot table over a range that misses new rows. Use an Excel table as the source so the pivot grows with the data. ([Lookups, pivot tables and charts](../04-developer-tools-and-workflow/04-spreadsheets/02-lookups-pivot-tables-and-charts.md))
- A spill range blocked by a value in the way gives `#SPILL!`. Clear the cells under the formula. ([Lookups, pivot tables and charts](../04-developer-tools-and-workflow/04-spreadsheets/02-lookups-pivot-tables-and-charts.md))
- Opening a CSV by double-clicking it, then saving over it. Excel has already guessed the types, and the save writes the damage back. Import it with a Text column type, or read it in code. ([Spreadsheets, CSV and SQL](../04-developer-tools-and-workflow/04-spreadsheets/03-spreadsheets-csv-and-sql.md))
- A `.csv` with a byte order mark or a non-UTF-8 encoding. The first column name shows up as `﻿date`, or accented letters break. Read with `encoding="utf-8-sig"` in Python, or re-export as CSV UTF-8. ([Spreadsheets, CSV and SQL](../04-developer-tools-and-workflow/04-spreadsheets/03-spreadsheets-csv-and-sql.md))
- Treating spreadsheet totals as the source of truth. A CSV has no formulas, so recompute totals in SQL or Python and compare. ([Spreadsheets, CSV and SQL](../04-developer-tools-and-workflow/04-spreadsheets/03-spreadsheets-csv-and-sql.md))

## Discrete math for CS

- Negating `a and b` as `not a and not b`. De Morgan flips the connective too, so the correct form is `not a or not b`. When unsure, run the equivalence check from Example 1. ([Logic and truth tables](../05-discrete-math-for-cs/01-logic-and-truth-tables.md))
- Reading "if p then q" as also meaning "if q then p". "If the code is correct, the tests pass" does not mean "if the tests pass, the code is correct". ([Logic and truth tables](../05-discrete-math-for-cs/01-logic-and-truth-tables.md))
- Assuming SQL conditions have only two outcomes. With `NULL` a comparison can be unknown, so `NOT (x = 1)` does not select every row that `x = 1` skipped. See `NULL` and [three-valued logic](../10-databases-sql-and-postgres/02-querying/02-null-and-three-valued-logic.md). ([Logic and truth tables](../05-discrete-math-for-cs/01-logic-and-truth-tables.md))
- `UNION` removes duplicate rows, while `UNION ALL` keeps them. In the shop example, `UNION ALL` of the two groups returns 77 rows (33 + 44) instead of 68. Use plain `UNION` when you want set behaviour. ([Sets, functions and relations](../05-discrete-math-for-cs/02-sets-functions-and-relations.md))
- Expecting an order from a set. Python does not promise one, so use `sorted(s)` when printing or testing. Also, `{}` is an empty dict; an empty set is `set()`. ([Sets, functions and relations](../05-discrete-math-for-cs/02-sets-functions-and-relations.md))
- Reading `A EXCEPT B` as symmetric. It keeps what is in A but not in B. For rows that are in exactly one of the two, use `a ^ b` in Python. ([Sets, functions and relations](../05-discrete-math-for-cs/02-sets-functions-and-relations.md))
- Treating passing tests as a proof. Tests sample the inputs; the opening example passed 40 cases and was still false. Use tests to find counterexamples and a proof to cover all cases. ([Proof techniques and induction](../05-discrete-math-for-cs/03-proof-techniques-and-induction.md))
- Skipping the base case, or proving a step that never starts. If the base case is missing, the chain has no first domino. In code, this is a recursive function with no stopping case. ([Proof techniques and induction](../05-discrete-math-for-cs/03-proof-techniques-and-induction.md))
- Using the claim in its own proof. In the step you may assume $P(k)$ but must prove $P(k+1)$ without assuming it. ([Proof techniques and induction](../05-discrete-math-for-cs/03-proof-techniques-and-induction.md))
- Using $n^k$ when items cannot repeat, or $P(n, k)$ when they can. Ask two questions first: does order matter, and can I reuse an item? Check with `itertools` on a small case, such as `permutations("ABCD", 2)`, which gives $12 = 4 \times 3$. ([Counting](../05-discrete-math-for-cs/04-counting.md))
- Assuming an exponential or factorial space can be searched. $10!$ is 3,628,800, which is quick, but $20!$ is about $2.4 \times 10^{18}$. This is why trying every route in a delivery problem stops working at around 20 stops. ([Counting](../05-discrete-math-for-cs/04-counting.md))
- Counting an "at least one" condition directly. "At least one digit" is hard to count, but "all letters" is easy. Use the complement rule: total minus the ones with none. ([Counting](../05-discrete-math-for-cs/04-counting.md))
- Multiplying probabilities that are not independent. A hundred services that are each up 99.9% of the time are all up with probability $0.999^{100} \approx 0.905$ only if their failures are independent. If they share a database or a network link, failures come together and the real figure differs. ([Discrete probability](../05-discrete-math-for-cs/05-discrete-probability.md))
- Reading $P(A \mid B)$ as $P(B \mid A)$. "95% of bots are flagged" is not "95% of flagged requests are bots". Example 2 shows the second is 16.1%. ([Discrete probability](../05-discrete-math-for-cs/05-discrete-probability.md))
- Expecting a streak to reverse. If each request fails independently with chance 1%, a failure just now does not make the next one less likely. The gambler's fallacy treats independent events as if they remembered. ([Discrete probability](../05-discrete-math-for-cs/05-discrete-probability.md))
- Confusing a tree with a binary tree. A tree is any connected graph with no cycle, and a node can have any number of children. A binary search tree is a special case with at most two children per node and an ordering rule. ([Graphs and trees](../05-discrete-math-for-cs/06-graphs-and-trees.md))
- Adding a link to a tree and still calling it a tree. One extra edge, such as a symbolic link or a circular import, makes a cycle. Code that walks the structure recursively then never ends unless it tracks the vertices it has seen. ([Graphs and trees](../05-discrete-math-for-cs/06-graphs-and-trees.md))
- Storing a sparse graph as a matrix. A matrix for 1,000 vertices has 1,000,000 cells even if each vertex has 3 edges, while an adjacency list has about 3,000 entries. ([Graphs and trees](../05-discrete-math-for-cs/06-graphs-and-trees.md))
- Negative numbers. In Python, `-7 % 5` is `3`, which matches the math definition. In JavaScript, C and Java, `-7 % 5` is `-2`, because `%` there is the remainder with the sign of the first operand. A hash that can be negative then gives a negative bucket index. Use `((a % n) + n) % n` in those languages. ([Modular arithmetic](../05-discrete-math-for-cs/07-modular-arithmetic.md))
- Dividing modulo $n$. `a / b % n` is not the same as multiplying by an inverse, and for a modulus that is not prime some numbers have no inverse at all. Use `pow(b, -1, n)`. ([Modular arithmetic](../05-discrete-math-for-cs/07-modular-arithmetic.md))
- Using textbook RSA for real. Without padding, the same message always gives the same ciphertext, and small messages can be recovered. Use a vetted library, which applies padding (OAEP) and handles key sizes. ([Modular arithmetic](../05-discrete-math-for-cs/07-modular-arithmetic.md))
- Off-by-one in the bounds of a sum. `range(n)` covers $0$ to $n - 1$, so a loop over `range(n)` adds $n$ terms, and the inner loop in Example 1 stops one short. Test the formula on $n = 3$ before trusting it. ([Sums, logs and recurrences](../05-discrete-math-for-cs/08-sums-logs-and-recurrences.md))
- Treating $\log n$ as if it needs a base. In Big O it does not, but in an exact count it does. Binary search is $\log_2$ because it halves; a tree where every node has 100 children needs about $\log_{100} n$ levels. ([Sums, logs and recurrences](../05-discrete-math-for-cs/08-sums-logs-and-recurrences.md))
- Adding the cost of one level and forgetting the number of levels. For $T(n) = 2T(n/2) + n$, each level costs $n$, but there are about $\log_2 n$ of them. The total is not $n$. ([Sums, logs and recurrences](../05-discrete-math-for-cs/08-sums-logs-and-recurrences.md))

## Data structures and algorithms

- Adding the costs of nested loops. A loop inside a loop multiplies; two loops side by side add. ([Big O and runtime](../06-data-structures-and-algorithms/01-analysis/01-big-o-and-runtime.md))
- Reading $O(n)$ as "takes $n$ seconds" or $O(1)$ as "fast". $O(1)$ only says the cost doesn't grow with $n$; a call that always costs 200 ms is still $O(1)$. ([Big O and runtime](../06-data-structures-and-algorithms/01-analysis/01-big-o-and-runtime.md))
- Calling the answer $O(n^2 + n)$ or $O(3n)$. Write $O(n^2)$ and $O(n)$. ([Big O and runtime](../06-data-structures-and-algorithms/01-analysis/01-big-o-and-runtime.md))
- Confusing amortized with average case. Average case assumes typical or random inputs and can be broken by a bad input. An amortized bound holds for every sequence of operations. ([Space and amortized analysis](../06-data-structures-and-algorithms/01-analysis/02-space-and-amortized-analysis.md))
- Forgetting the call stack. A recursive function that builds no lists is still $O(\text{depth})$ in space. Recursing on `items[1:]` is worse: each call copies the rest of the list, so time and space both become $O(n^2)$. Pass an index instead. ([Space and amortized analysis](../06-data-structures-and-algorithms/01-analysis/02-space-and-amortized-analysis.md))
- Forgetting the work outside the calls. Merge sort's merge step is $n$ work per level; leaving it out gives $T(n) = 2T(n/2)$, which solves to $O(n)$ and understates merge sort by a factor of $\log n$. ([Analysing recursive algorithms](../06-data-structures-and-algorithms/01-analysis/03-analysing-recursive-algorithms.md))
- Using the master theorem on $T(n-1)$ forms or on uneven splits. It needs equal pieces of size $n/b$. Unroll the recurrence instead. ([Analysing recursive algorithms](../06-data-structures-and-algorithms/01-analysis/03-analysing-recursive-algorithms.md))
- Adding `@cache` to everything. It helps only with overlapping subproblems, it needs hashable arguments (a list argument raises `TypeError`), and it keeps every result in memory. ([Analysing recursive algorithms](../06-data-structures-and-algorithms/01-analysis/03-analysing-recursive-algorithms.md))
- Calling `list.insert(0, x)` or `list.pop(0)` inside a loop. Each call is $O(n)$, so the loop is $O(n^2)$. Append and pop at the end, or switch to a deque. ([Arrays and dynamic arrays](../06-data-structures-and-algorithms/02-data-structures/01-arrays-and-dynamic-arrays.md))
- Assuming `append` is always cheap. The average is $O(1)$, but one append in a latency-sensitive path can trigger a full copy. Reserve space up front when you know the size, for example `[0] * n`. ([Arrays and dynamic arrays](../06-data-structures-and-algorithms/02-data-structures/01-arrays-and-dynamic-arrays.md))
- Losing the rest of the list by overwriting `node.next` before saving it. Always keep the old pointer in a variable first. ([Linked lists](../06-data-structures-and-algorithms/02-data-structures/02-linked-lists.md))
- Forgetting the empty list and the one-node list. Code that does `self.head.next` crashes with `AttributeError` when `head` is `None`. Test those two cases first. ([Linked lists](../06-data-structures-and-algorithms/02-data-structures/02-linked-lists.md))
- Reading "$O(1)$ insert" as "$O(1)$ insert at position $i$". Finding position $i$ is the $O(n)$ part. ([Linked lists](../06-data-structures-and-algorithms/02-data-structures/02-linked-lists.md))
- Using a `list` as a queue with `pop(0)`. Popping 100,000 items this way took 0.588 s on the author's machine, against 0.003 s for `deque.popleft()`. The gap grows with the length of the queue. ([Stacks and queues](../06-data-structures-and-algorithms/02-data-structures/03-stacks-and-queues.md))
- Calling `pop()` on an empty stack or `popleft()` on an empty deque. Both raise `IndexError`. Check `if stack:` first. ([Stacks and queues](../06-data-structures-and-algorithms/02-data-structures/03-stacks-and-queues.md))
- Indexing into the middle of a `deque`. It is $O(n)$, so if you need random access, use a `list`. ([Stacks and queues](../06-data-structures-and-algorithms/02-data-structures/03-stacks-and-queues.md))
- Using a mutable object as a key, or changing an object after using it as a key. Use tuples, strings or numbers. ([Hash tables](../06-data-structures-and-algorithms/02-data-structures/04-hash-tables.md))
- Relying on `set` iteration order, or on the order of `hash()` for strings. String hashes change between runs on purpose (hash randomization), so a program that prints a `set` of strings can print in different orders on different days. Sort before printing. ([Hash tables](../06-data-structures-and-algorithms/02-data-structures/04-hash-tables.md))
- Assuming the average case is the guarantee. A hostile input can make many keys collide. Web servers that parse attacker-supplied keys depend on randomized hashes for this reason. ([Hash tables](../06-data-structures-and-algorithms/02-data-structures/04-hash-tables.md))
- Checking a BST by comparing each node only to its direct children. Every node in the root's left subtree must be smaller than the root, not just smaller than its own parent. Check each node against a (low, high) range that narrows as you go down. ([Trees and binary search trees](../06-data-structures-and-algorithms/02-data-structures/05-trees-and-binary-search-trees.md))
- Assuming "tree" means $O(\log n)$. That holds only when the tree is balanced. Say "balanced BST" or name the library structure. ([Trees and binary search trees](../06-data-structures-and-algorithms/02-data-structures/05-trees-and-binary-search-trees.md))
- Forgetting duplicates. This code ignores an equal key; a database might store both. Decide the rule first. ([Trees and binary search trees](../06-data-structures-and-algorithms/02-data-structures/05-trees-and-binary-search-trees.md))
- Expecting `heapq` to give a max-heap, or printing the list and expecting it sorted. The list has the heap property only. Pop in a loop to get sorted order. ([Heaps and priority queues](../06-data-structures-and-algorithms/02-data-structures/06-heaps-and-priority-queues.md))
- Pushing items that cannot be compared. Two equal priorities make Python compare the items next, and if those are dicts or custom objects it raises `TypeError`. Add a unique counter: `(priority, counter, item)`. ([Heaps and priority queues](../06-data-structures-and-algorithms/02-data-structures/06-heaps-and-priority-queues.md))
- Mutating an item's priority while it sits in the heap. The heap does not notice, and the order silently breaks. Push a new entry instead and skip stale ones when you pop. ([Heaps and priority queues](../06-data-structures-and-algorithms/02-data-structures/06-heaps-and-priority-queues.md))
- Reading `adj[x]` on a `defaultdict` for a vertex that is not in the graph. It silently creates an empty entry, so a later "is this vertex present?" check gives the wrong answer. Use `x in adj` or `adj.get(x, [])`. ([Graphs and representations](../06-data-structures-and-algorithms/02-data-structures/07-graphs-and-representations.md))
- Storing an undirected edge in only one direction. Then `A` lists `B` but `B` does not list `A`, and traversals miss edges. Add both. ([Graphs and representations](../06-data-structures-and-algorithms/02-data-structures/07-graphs-and-representations.md))
- Using a matrix for a large sparse graph. A graph with a million users needs $10^{12}$ cells, which will not fit in memory, but its list needs only about $V + E$ entries. ([Graphs and representations](../06-data-structures-and-algorithms/02-data-structures/07-graphs-and-representations.md))
- Forgetting the end marker in a trie. Without it, `contains("ca")` would be true whenever `car` is stored, because a path exists. ([Tries and union find](../06-data-structures-and-algorithms/02-data-structures/08-tries-and-union-find.md))
- Calling `find` only once per element and then reading `parent[x]` directly. Before the final compression, `parent[x]` may be an intermediate node, not the root. Compare `find(a)` with `find(b)`. ([Tries and union find](../06-data-structures-and-algorithms/02-data-structures/08-tries-and-union-find.md))
- Reaching for a trie when a sorted list and `bisect` would do. The trie costs far more memory per word. ([Tries and union find](../06-data-structures-and-algorithms/02-data-structures/08-tries-and-union-find.md))
- Running it on unsorted data. `binary_search([5, 1, 4, 2, 3], 1)` returns `-1` even though 1 is in the list, because the first comparison throws away the half that holds it. Nothing raises an error, so check that the input is sorted. ([Binary search](../06-data-structures-and-algorithms/03-algorithms/01-binary-search.md))
- Mixing loop styles. `while lo <= hi` goes with `hi = len(a) - 1` and `hi = mid - 1`. `while lo < hi` goes with `hi = len(a)` and `hi = mid`. Pick one style per function and do not swap half of it. ([Binary search](../06-data-structures-and-algorithms/03-algorithms/01-binary-search.md))
- Assuming `mid = (lo + hi) // 2` is safe everywhere. In Python integers do not overflow. In Java, C or C++ with 32-bit `int`, `lo + hi` can; use `lo + (hi - lo) // 2`. ([Binary search](../06-data-structures-and-algorithms/03-algorithms/01-binary-search.md))
- `x = my_list.sort()` sets `x` to `None`. `list.sort()` sorts in place and returns nothing; `sorted(my_list)` returns a new list. ([Sorting](../06-data-structures-and-algorithms/03-algorithms/02-sorting.md))
- Writing your own sort for production code. The built-in one is stable, tested, written in C and adaptive. Hand-written sorts belong in learning and interviews. ([Sorting](../06-data-structures-and-algorithms/03-algorithms/02-sorting.md))
- Assuming `n log n` always wins. For 20 items insertion sort is fine, which is why library sorts switch to it for small pieces. ([Sorting](../06-data-structures-and-algorithms/03-algorithms/02-sorting.md))
- Marking a node visited when you take it out of the frontier instead of when you add it. The same node can then be queued many times, which wastes time and memory. Mark on the way in. ([BFS and DFS](../06-data-structures-and-algorithms/03-algorithms/03-bfs-and-dfs.md))
- Using a plain `list` and `pop(0)` as the BFS queue. Removing from the front of a list is $O(n)$, so BFS becomes slow. Use `collections.deque`. ([BFS and DFS](../06-data-structures-and-algorithms/03-algorithms/03-bfs-and-dfs.md))
- Recursive DFS on a long chain. Python's default recursion limit is 1,000 calls, and a 5,000-node path raises `RecursionError`. Use an explicit stack for big inputs. ([BFS and DFS](../06-data-structures-and-algorithms/03-algorithms/03-bfs-and-dfs.md))
- Using Dijkstra when weights can be negative, such as a price difference or a refund edge. Use Bellman-Ford, or check that all weights are at least 0 before you start. ([Shortest paths](../06-data-structures-and-algorithms/03-algorithms/04-shortest-paths.md))
- Using BFS on a weighted graph and calling the result "shortest". BFS minimizes edges, not total weight. ([Shortest paths](../06-data-structures-and-algorithms/03-algorithms/04-shortest-paths.md))
- Leaving out the stale-entry check (`if d > dist[node]: continue`). The answer is still right, but the same node is processed many times and the loop does extra work. ([Shortest paths](../06-data-structures-and-algorithms/03-algorithms/04-shortest-paths.md))
- Trusting a greedy rule because it passes the examples you tried. Try small cases with ties and with an item that is attractive but blocks several others, like meeting `c` above. ([Greedy algorithms](../06-data-structures-and-algorithms/03-algorithms/05-greedy-algorithms.md))
- Picking the wrong greedy rule for a problem that is greedy. Interval scheduling fails with earliest start and with shortest duration; only earliest finish is correct. ([Greedy algorithms](../06-data-structures-and-algorithms/03-algorithms/05-greedy-algorithms.md))
- Sorting by one field when ties matter. If two meetings end at the same time, either is safe here, but in other problems the tie-break changes the answer. ([Greedy algorithms](../06-data-structures-and-algorithms/03-algorithms/05-greedy-algorithms.md))
- Memoizing with an argument that can change, such as a list. `@cache` needs hashable arguments, so pass indexes or tuples, not lists. ([Dynamic programming](../06-data-structures-and-algorithms/03-algorithms/06-dynamic-programming.md))
- Deep memoized recursion. A call chain 5,000 deep raises `RecursionError` at Python's default limit of 1,000. Use the table version, or recurse on a smaller state. ([Dynamic programming](../06-data-structures-and-algorithms/03-algorithms/06-dynamic-programming.md))
- A wrong state. If the recurrence needs information the state lacks (for example, what you chose earlier), the answers are wrong or the table is too small. Add that information to the state. ([Dynamic programming](../06-data-structures-and-algorithms/03-algorithms/06-dynamic-programming.md))
- Coding at once. Without steps 1 and 2 you solve a different problem from the one asked, and the interviewer cannot tell what you were thinking. Spend the first five minutes talking. ([How to approach a problem](../06-data-structures-and-algorithms/04-leetcode-patterns/01-how-to-approach-a-problem.md))
- Testing only the example the problem gave you. Those cases pass by design. Run the empty input, one element, duplicates and the largest size. ([How to approach a problem](../06-data-structures-and-algorithms/04-leetcode-patterns/01-how-to-approach-a-problem.md))
- Trying to recall the problem's solution instead of reasoning. If you recognize it, still explain the brute force and the bottleneck, or the interviewer cannot tell recall from understanding. ([How to approach a problem](../06-data-structures-and-algorithms/04-leetcode-patterns/01-how-to-approach-a-problem.md))
- Using opposite-end pointers on unsorted data. The "this value cannot be in the answer" argument needs the order. Sort first (and give up the original indices) or use a hash map. ([Two pointers and sliding window](../06-data-structures-and-algorithms/04-leetcode-patterns/02-two-pointers-and-sliding-window.md))
- Shrinking with `if` instead of `while`. One new element can invalidate the window by more than one step, so the left edge may need to move several times. ([Two pointers and sliding window](../06-data-structures-and-algorithms/04-leetcode-patterns/02-two-pointers-and-sliding-window.md))
- Sliding windows on arrays with negative numbers when the condition is a sum. Adding an element no longer makes the sum only grow, so shrinking is no longer safe. That case is a [prefix sum](../06-data-structures-and-algorithms/04-leetcode-patterns/03-hashing-and-prefix-sums.md) problem. ([Two pointers and sliding window](../06-data-structures-and-algorithms/04-leetcode-patterns/02-two-pointers-and-sliding-window.md))
- Forgetting `{0: 1}` in the prefix counter. Subarrays that start at index 0 are never counted, and the code passes the sample but fails on a case such as `[3]` with $k = 3$. ([Hashing and prefix sums](../06-data-structures-and-algorithms/04-leetcode-patterns/03-hashing-and-prefix-sums.md))
- Updating the map before the lookup. A value then pairs with itself in Two Sum, and a prefix matches itself when $k = 0$. ([Hashing and prefix sums](../06-data-structures-and-algorithms/04-leetcode-patterns/03-hashing-and-prefix-sums.md))
- Assuming a hash map lookup is always $O(1)$. It is $O(1)$ on average. Only hashable values can be keys, so a list must become a tuple first. ([Hashing and prefix sums](../06-data-structures-and-algorithms/04-leetcode-patterns/03-hashing-and-prefix-sums.md))
- Storing values instead of indices. You then cannot compute how far away the answer is or how wide a rectangle is. ([Stacks and monotonic stacks](../06-data-structures-and-algorithms/04-leetcode-patterns/04-stacks-and-monotonic-stacks.md))
- Using `>` where the problem needs `>=` (or the reverse). With equal heights the choice changes which bar owns the width, and equal values are where random tests catch it. ([Stacks and monotonic stacks](../06-data-structures-and-algorithms/04-leetcode-patterns/04-stacks-and-monotonic-stacks.md))
- Forgetting the leftover items. After the loop, anything still on the stack never found a bigger item. Leave the default, or use a sentinel as in 84. ([Stacks and monotonic stacks](../06-data-structures-and-algorithms/04-leetcode-patterns/04-stacks-and-monotonic-stacks.md))
- Forgetting the base case `None` in a tree function. The call on a missing child then crashes with `AttributeError: 'NoneType' object has no attribute 'left'`. ([Tree and graph problems](../06-data-structures-and-algorithms/04-leetcode-patterns/05-tree-and-graph-problems.md))
- Marking a grid cell visited only when you pop it. The same cell can be added many times. Mark when you add it. ([Tree and graph problems](../06-data-structures-and-algorithms/04-leetcode-patterns/05-tree-and-graph-problems.md))
- Recursion depth. Python's default limit is 1,000 calls, so a chain-shaped tree or a huge grid flood can raise `RecursionError`. Use an explicit stack or queue for large inputs. ([Tree and graph problems](../06-data-structures-and-algorithms/04-leetcode-patterns/05-tree-and-graph-problems.md))
- Appending `path` instead of `path[:]`. Every stored answer is the same list object, and at the end they all show the final empty path. ([Backtracking](../06-data-structures-and-algorithms/04-leetcode-patterns/06-backtracking.md))
- Forgetting the undo (`pop`, or `used[i] = False`). The next branch then starts with stale choices and results are missing or wrong. ([Backtracking](../06-data-structures-and-algorithms/04-leetcode-patterns/06-backtracking.md))
- Using backtracking when the input is large. If $n$ is 1,000, a solution that lists every subset cannot finish. Re-read the constraints. ([Backtracking](../06-data-structures-and-algorithms/04-leetcode-patterns/06-backtracking.md))
- A greedy rule where DP is needed. Coin Change with `[1, 3, 4]` is the standard counter-example. Test greedy against a brute force before trusting it. ([DP patterns](../06-data-structures-and-algorithms/04-leetcode-patterns/07-dp-patterns.md))
- Wrong base cases. `dp[0]` for Coin Change is 0, not infinity, and the table row and column for the empty string in LCS must exist. Run the empty and amount-0 inputs. ([DP patterns](../06-data-structures-and-algorithms/04-leetcode-patterns/07-dp-patterns.md))
- Filling the table in the wrong order, so a cell reads a value that is still its initial 0. Each cell's inputs must be filled first. ([DP patterns](../06-data-structures-and-algorithms/04-leetcode-patterns/07-dp-patterns.md))
- Using a max-heap of everything and popping $k$ times. It works, but costs $O(n + k \log n)$ and keeps all $n$ items. Python's `heapq` is a min-heap only; to get a max-heap, push negated values. ([Heaps, intervals and top-k](../06-data-structures-and-algorithms/04-leetcode-patterns/08-heaps-intervals-and-top-k.md))
- Forgetting to sort the intervals first, or sorting by end instead of start. The sweep depends on the order. ([Heaps, intervals and top-k](../06-data-structures-and-algorithms/04-leetcode-patterns/08-heaps-intervals-and-top-k.md))
- Strict versus non-strict comparison at endpoints. Whether `[1, 4]` and `[4, 5]` overlap is stated in the problem. Read it, and test the touching case. ([Heaps, intervals and top-k](../06-data-structures-and-algorithms/04-leetcode-patterns/08-heaps-intervals-and-top-k.md))

## Networking

- Reading `* * *` in a traceroute as "the network is broken here". Many routers ignore probes. If later hops answer, traffic is passing through. ([Packets, routers and the internet](../07-networking/01-how-the-internet-works/01-packets-routers-and-the-internet.md))
- Reading the latency of hop 5 as the time spent on hop 5. Each line is the time to that router and back. It includes every earlier hop and the router's own low-priority handling of probe replies, so one slow line in the middle with fast lines after it is usually not a problem. ([Packets, routers and the internet](../07-networking/01-how-the-internet-works/01-packets-routers-and-the-internet.md))
- Assuming every `172.x.x.x` address is private. Only `172.16.0.0` to `172.31.255.255` is. ([IP addresses, subnets and NAT](../07-networking/01-how-the-internet-works/02-ip-addresses-subnets-and-nat.md))
- Starting a dev server bound to `0.0.0.0` on public Wi-Fi. Anyone on that network can reach it. Bind to `127.0.0.1` unless you need other devices. ([IP addresses, subnets and NAT](../07-networking/01-how-the-internet-works/02-ip-addresses-subnets-and-nat.md))
- Choosing the same private range at home and for a VPN or a cloud network. When two networks overlap, packets for an address go to the wrong one. Cloud networks are planned with CIDR blocks that do not overlap. ([IP addresses, subnets and NAT](../07-networking/01-how-the-internet-works/02-ip-addresses-subnets-and-nat.md))
- Saying TCP is "safe" or "secure". It is reliable, which means delivered and in order. It does not encrypt anything; that is [TLS](../07-networking/02-web-protocols/03-tls-https-and-certificates.md), one layer up. ([Network layers, TCP and UDP](../07-networking/01-how-the-internet-works/03-network-layers-tcp-and-udp.md))
- Assuming a UDP `sendto` that returned without error was delivered. It only means the operating system accepted the datagram. ([Network layers, TCP and UDP](../07-networking/01-how-the-internet-works/03-network-layers-tcp-and-udp.md))
- Using UDP for something that must not lose data (a file, a payment) without adding acknowledgements and retries. Use TCP, or a protocol such as QUIC that provides them. ([Network layers, TCP and UDP](../07-networking/01-how-the-internet-works/03-network-layers-tcp-and-udp.md))
- Assuming one `recv` returns one whole message. TCP is a stream of bytes with no message boundaries, so a read may return half a message or two messages glued together. Protocols add a length prefix or a delimiter, for example the blank line that ends HTTP headers. ([Ports and sockets](../07-networking/01-how-the-internet-works/04-ports-and-sockets.md))
- Killing a server and restarting it at once, then seeing "address already in use" even though no process is left. Closed connections stay in a `TIME_WAIT` state for a short time. Servers set the `SO_REUSEADDR` option to rebind straight away. ([Ports and sockets](../07-networking/01-how-the-internet-works/04-ports-and-sockets.md))
- Confusing the port a server listens on with the port a client uses. Your browser's port is random; only the server's is meaningful. ([Ports and sockets](../07-networking/01-how-the-internet-works/04-ports-and-sockets.md))
- "I changed the DNS record and nothing happened." Caches keep the old answer until its TTL runs out, and your browser and OS have caches too. Before a planned move, lower the TTL a day ahead. Changing which name servers a domain uses (at the registrar) can take much longer, because the TLD servers cache that information. ([DNS and domains](../07-networking/01-how-the-internet-works/05-dns-and-domains.md))
- Putting a CNAME on the bare domain (`example.com`) when it already has other records such as MX. A CNAME means "this name is only an alias", so it can't share a name with other records. Use an A record, or the ALIAS-style record your DNS host offers. ([DNS and domains](../07-networking/01-how-the-internet-works/05-dns-and-domains.md))
- Assuming "the site is down" when DNS is the problem. `curl` by IP address works while the name fails. Test both. ([DNS and domains](../07-networking/01-how-the-internet-works/05-dns-and-domains.md))
- Using `GET` for actions that change data. Browsers, crawlers and caches assume `GET` is safe and may repeat or prefetch it, so a `GET /delete?id=5` link can delete things on its own. ([HTTP requests and responses](../07-networking/02-web-protocols/01-http-requests-and-responses.md))
- Returning `200` with an error message in the body. Clients and monitoring tools read the status code first. Use `4xx` for the caller's mistake and `5xx` for yours. ([HTTP requests and responses](../07-networking/02-web-protocols/01-http-requests-and-responses.md))
- Assuming `PUT` and `POST` are interchangeable. `PUT` replaces a resource at a known URL and is idempotent; `POST` is not. ([HTTP requests and responses](../07-networking/02-web-protocols/01-http-requests-and-responses.md))
- Thinking `no-cache` means "do not cache". It means "revalidate before use". For data that must never be stored, use `no-store`. ([HTTP headers, cookies and caching](../07-networking/02-web-protocols/02-http-headers-cookies-and-caching.md))
- Putting a session ID or token in `localStorage` or a cookie without `HttpOnly`. Any script on the page, including a compromised dependency, can read it. ([HTTP headers, cookies and caching](../07-networking/02-web-protocols/02-http-headers-cookies-and-caching.md))
- Long `max-age` on a file whose name never changes. Users keep the old copy. Give the file a hashed name or use a short `max-age` with an `ETag`. ([HTTP headers, cookies and caching](../07-networking/02-web-protocols/02-http-headers-cookies-and-caching.md))
- Turning verification off to "fix" an error (`curl -k`, `verify=False` in Python `requests`, `NODE_TLS_REJECT_UNAUTHORIZED=0`). The connection is then encrypted to anyone, including an attacker. Fix the certificate; use `-k` only for a throwaway local test. ([TLS, HTTPS and certificates](../07-networking/02-web-protocols/03-tls-https-and-certificates.md))
- Believing the padlock proves a site is safe. It proves only an encrypted connection to the named domain. ([TLS, HTTPS and certificates](../07-networking/02-web-protocols/03-tls-https-and-certificates.md))
- Letting a certificate expire. Monitor expiry dates, because a renewal job fails silently. ([TLS, HTTPS and certificates](../07-networking/02-web-protocols/03-tls-https-and-certificates.md))
- Trusting the client. Anything in the browser, including hidden form fields, prices in JavaScript and a role stored in a cookie, can be changed by the user. Validate and authorize on the server. ([Client-server architecture](../07-networking/02-web-protocols/04-client-server-architecture.md))
- Storing sessions or uploaded files on one app server's disk or memory, then scaling to two servers. Users get logged out at random. Use a shared store. ([Client-server architecture](../07-networking/02-web-protocols/04-client-server-architecture.md))
- Polling too fast. A client polling every second with 10,000 users is 10,000 requests per second for mostly empty answers. ([Client-server architecture](../07-networking/02-web-protocols/04-client-server-architecture.md))
- Trusting `X-Forwarded-For` from anyone. A client can send its own value. Accept it only from your proxy's address, and take the right-most entry your proxy added. ([Proxies and CDNs](../07-networking/02-web-protocols/05-proxies-and-cdns.md))
- Caching personalized pages at the CDN. If `/account` has no `Cache-Control: private`, one user's page can be served to another. Set it explicitly and test while logged out. ([Proxies and CDNs](../07-networking/02-web-protocols/05-proxies-and-cdns.md))
- Forgetting that a proxy can return stale content after you deploy. Purge the CDN cache or use hashed file names. ([Proxies and CDNs](../07-networking/02-web-protocols/05-proxies-and-cdns.md))
- Reaching for WebSockets when SSE or polling would do. A WebSocket server must track every open connection, and a rolling deploy drops them all. ([WebSockets and real-time communication](../07-networking/02-web-protocols/06-websockets-and-real-time.md))
- No reconnect logic. Connections break on mobile networks and sleep. The client must reconnect and ask for what it missed (SSE does reconnect, with a `Last-Event-ID` header you can use). ([WebSockets and real-time communication](../07-networking/02-web-protocols/06-websockets-and-real-time.md))
- Skipping authentication on the upgrade request. Check the user before accepting the upgrade, and check the `Origin` header. ([WebSockets and real-time communication](../07-networking/02-web-protocols/06-websockets-and-real-time.md))
- Treating a failed `ping` as proof a server is down. Many hosts block ICMP. If `curl -v` connects, the server is up. ([Network debugging tools](../07-networking/02-web-protocols/07-network-debugging-tools.md))
- Reading `traceroute` stars as the break. Only a path that stops answering all the way to the end points to a fault. ([Network debugging tools](../07-networking/02-web-protocols/07-network-debugging-tools.md))
- Debugging in the browser only. Caches, extensions and cookies change what you see. Reproduce with `curl` to remove them. ([Network debugging tools](../07-networking/02-web-protocols/07-network-debugging-tools.md))

## Front end

- Putting a large synchronous script in `<head>` "so it loads first". It loads first and holds up everything else. Use `defer`, or place the script at the end of `<body>`. ([How browsers render pages](../08-front-end/01-html-css-and-the-browser/01-how-browsers-render-pages.md))
- Reading `element.offsetHeight` right after changing styles in a loop. The read forces the browser to run layout immediately each time. Batch all the writes, then do the reads. ([How browsers render pages](../08-front-end/01-html-css-and-the-browser/01-how-browsers-render-pages.md))
- Judging speed by feel on a fast laptop. Use the Performance panel with network and CPU throttling turned on. ([How browsers render pages](../08-front-end/01-html-css-and-the-browser/01-how-browsers-render-pages.md))
- Using a placeholder as a label. It disappears when the user types and is not reliably read by assistive tools. Keep a visible `<label>`. ([HTML](../08-front-end/01-html-css-and-the-browser/02-html.md))
- `<div>` or `<span>` with a click handler instead of `<button>`. You lose keyboard support, focus and the role. Use the real element. ([HTML](../08-front-end/01-html-css-and-the-browser/02-html.md))
- Trusting browser validation. It checks the form on the client only; the server must repeat every check. ([HTML](../08-front-end/01-html-css-and-the-browser/02-html.md))
- Forgetting that the default is `content-box`. A `width: 100%` box with padding becomes wider than its parent and scrolls sideways. Set `box-sizing: border-box`. ([CSS and the box model](../08-front-end/01-html-css-and-the-browser/03-css-and-the-box-model.md))
- Using `px` for font sizes. Users who raise their browser's default text size get no change. Use `rem`. ([CSS and the box model](../08-front-end/01-html-css-and-the-browser/03-css-and-the-box-model.md))
- Fighting specificity with `!important` or longer and longer selectors. Keep selectors short (one class) and fix the order instead. ([CSS and the box model](../08-front-end/01-html-css-and-the-browser/03-css-and-the-box-model.md))
- Setting `display: flex` on the wrong element. It affects the children of that element only. If nothing moves, check that you styled the parent. ([Layout with flexbox, grid and responsive design](../08-front-end/01-html-css-and-the-browser/04-layout-flexbox-grid-and-responsive.md))
- Using `width: 100vw`. It includes the scrollbar and causes a sideways scroll bar. Use `width: 100%` for fluid blocks. ([Layout with flexbox, grid and responsive design](../08-front-end/01-html-css-and-the-browser/04-layout-flexbox-grid-and-responsive.md))
- Desktop-first CSS with `max-width` queries stacked on top of each other. It is easy to leave a middle size broken. Start small and add `min-width` queries. ([Layout with flexbox, grid and responsive design](../08-front-end/01-html-css-and-the-browser/04-layout-flexbox-grid-and-responsive.md))
- Assuming a score of 100 in Lighthouse means the page is accessible. Automated tools cover only a minority of the success criteria. Always add a keyboard pass. ([Accessibility](../08-front-end/01-html-css-and-the-browser/05-accessibility.md))
- `outline: none` or `outline: 0` to remove the "ugly" focus ring. Keyboard users then cannot see where they are. Restyle it instead. ([Accessibility](../08-front-end/01-html-css-and-the-browser/05-accessibility.md))
- `aria-label` on a `div` to make it a button. The label gives it a name but not keyboard behaviour. Use `<button>`. ([Accessibility](../08-front-end/01-html-css-and-the-browser/05-accessibility.md))
- `for (const k in arr)` gives the indexes as strings (`"0"`, `"1"`). Use `for...of` for values. ([JavaScript for Python programmers](../08-front-end/02-javascript-and-typescript/01-javascript-for-python-programmers.md))
- `typeof null` is `"object"`, a historical quirk. Test for it with `x === null`, and for arrays with `Array.isArray(x)`. ([JavaScript for Python programmers](../08-front-end/02-javascript-and-typescript/01-javascript-for-python-programmers.md))
- Calling a detached method, such as `const f = obj.method; f()`, loses `this` and often throws a `TypeError`. Pass an arrow function or call `obj.method()`. ([JavaScript for Python programmers](../08-front-end/02-javascript-and-typescript/01-javascript-for-python-programmers.md))
- Running a script before the element exists. A `<script>` in the `<head>` runs before the body is parsed, so `querySelector` returns `null`. Add `type="module"` (modules are deferred) or put the script at the end of the body. ([The DOM and events](../08-front-end/02-javascript-and-typescript/02-the-dom-and-events.md))
- Calling the function instead of passing it. `addEventListener("click", save())` runs `save` now and registers its return value. Write `save` or `() => save()`. ([The DOM and events](../08-front-end/02-javascript-and-typescript/02-the-dom-and-events.md))
- A form without `preventDefault()` reloads the page and wipes your state, which looks like the code "did nothing". ([The DOM and events](../08-front-end/02-javascript-and-typescript/02-the-dom-and-events.md))
- Not checking `res.ok`. A 500 from the server does not throw, so the code carries on with an error body and fails later in `res.json()` or in the UI. ([Async JavaScript and the event loop](../08-front-end/02-javascript-and-typescript/03-async-javascript-and-the-event-loop.md))
- `await` inside `forEach` or a `map` callback. `forEach` does not wait for the async callbacks, so the code after it runs too early. Use a `for...of` loop to go one at a time, or `await Promise.all(items.map(...))` to go in parallel. ([Async JavaScript and the event loop](../08-front-end/02-javascript-and-typescript/03-async-javascript-and-the-event-loop.md))
- Forgetting `await`. You get a pending promise object where you expected data, and `console.log` prints `Promise { <pending> }`. ([Async JavaScript and the event loop](../08-front-end/02-javascript-and-typescript/03-async-javascript-and-the-event-loop.md))
- Trusting types for data from outside the program. `const user = (await res.json()) as User` tells the checker to believe you; if the server sends something else, the error appears later and far away. Validate with a schema library or narrow from `unknown`. ([TypeScript](../08-front-end/02-javascript-and-typescript/04-typescript.md))
- Silencing errors with `any` or `as`. Each one removes a check. Ask what the real type is instead. ([TypeScript](../08-front-end/02-javascript-and-typescript/04-typescript.md))
- Expecting types at runtime. `typeof` and `instanceof` work on values; `interface` and `type` are gone, so `if (x instanceof User)` on an interface is an error. ([TypeScript](../08-front-end/02-javascript-and-typescript/04-typescript.md))
- Committing `node_modules/`. It is large and regenerated by `npm install`. Put it in `.gitignore`; commit `package.json` and `package-lock.json`. ([npm, bundlers and Vite](../08-front-end/02-javascript-and-typescript/05-npm-bundlers-and-vite.md))
- Mixing package managers. If `package-lock.json` exists, use npm; running `yarn` or `pnpm` too creates a second lock file that disagrees. ([npm, bundlers and Vite](../08-front-end/02-javascript-and-typescript/05-npm-bundlers-and-vite.md))
- Putting secrets in front-end code or `VITE_` environment variables. Anything bundled into `dist/` is public. Keep secrets on the server. ([npm, bundlers and Vite](../08-front-end/02-javascript-and-typescript/05-npm-bundlers-and-vite.md))

## Back end

- Putting a rule only in the front end. A hidden button or a disabled form field is not a check; anyone can send the request with `curl`. Enforce every rule in the back end, and treat the front end's checks as convenience. ([What a back end does](../09-back-end/01-servers-and-apis/01-what-a-back-end-does.md))
- Keeping data in a variable. A `const cart = []` in the server works on your laptop and loses everything on restart, and two copies of the process behind a load balancer each hold a different cart. ([What a back end does](../09-back-end/01-servers-and-apis/01-what-a-back-end-does.md))
- Using a `Sync` function in a request handler (`readFileSync`, `pbkdf2Sync`). It is fine at startup, but inside a handler it stops every other request for its whole duration. Use the promise or callback version. ([Node.js and its runtime](../09-back-end/01-servers-and-apis/02-nodejs-and-its-runtime.md))
- Believing `async` makes code run in parallel. An `async` function that does a long loop still blocks the thread. `await` only helps when the thing awaited is I/O. ([Node.js and its runtime](../09-back-end/01-servers-and-apis/02-nodejs-and-its-runtime.md))
- A single thread does not mean one CPU core is the limit for the whole system. It means one process uses about one core for JavaScript. Start several processes to use the rest. ([Node.js and its runtime](../09-back-end/01-servers-and-apis/02-nodejs-and-its-runtime.md))
- Forgetting `next()` in middleware. The request then hangs until the client times out, because nothing sends a response and nothing continues. Either call `next()` or end the response. ([Express: routing and middleware](../09-back-end/01-servers-and-apis/03-express-routing-and-middleware.md))
- Registering `express.json()` after the routes. Order is execution order, so the handlers run first and see an empty `req.body`. ([Express: routing and middleware](../09-back-end/01-servers-and-apis/03-express-routing-and-middleware.md))
- Sending two responses, for example `res.json(...)` without `return` before more code that also responds. The second call throws "Cannot set headers after they are sent". Write `return res.status(404).json(...)`. ([Express: routing and middleware](../09-back-end/01-servers-and-apis/03-express-routing-and-middleware.md))
- Returning 200 with `{"error":...}` for failures. Clients, proxies and monitoring read the status code first. Use the right 4xx or 5xx code, with the error in the body. ([REST API design](../09-back-end/01-servers-and-apis/04-rest-api-design.md))
- Verbs in paths (`/getUser`, `/tasks/42/delete`). Use the method as the verb. For an action that isn't CRUD, model it as a resource: `POST /tasks/42/archive` is acceptable when no noun fits, but prefer `PATCH /tasks/42` with `{"archived": true}`. ([REST API design](../09-back-end/01-servers-and-apis/04-rest-api-design.md))
- Changing a response shape in place. Removing or renaming a field breaks clients you can't see. Add fields freely; ship breaking changes under a new version. ([REST API design](../09-back-end/01-servers-and-apis/04-rest-api-design.md))
- `res.status(500).json({ error: err.stack })` while developing, then shipping it. Stack traces reveal file paths, library versions and sometimes connection strings. Log them; don't send them. ([Validation and error handling](../09-back-end/01-servers-and-apis/05-validation-and-error-handling.md))
- Validating but then using `req.body`. The cleaned and defaulted values are in `parsed.data`; `req.body` is still the raw input, extra fields included. ([Validation and error handling](../09-back-end/01-servers-and-apis/05-validation-and-error-handling.md))
- Swallowing errors with an empty `catch`. The request then succeeds or hangs with no trace of why. Either handle the error or let it reach the central handler. ([Validation and error handling](../09-back-end/01-servers-and-apis/05-validation-and-error-handling.md))
- Choosing GraphQL or gRPC because it is fashionable. They add tooling, a schema to maintain and new failure modes. If one client talks to one back end with a handful of endpoints, REST is less work. ([Other API styles: GraphQL, gRPC and webhooks](../09-back-end/01-servers-and-apis/06-other-api-styles-graphql-grpc-webhooks.md))
- Trusting a webhook because it reached your URL. The URL is guessable and public. Without a signature check, anyone can post a fake "payment succeeded" event. ([Other API styles: GraphQL, gRPC and webhooks](../09-back-end/01-servers-and-apis/06-other-api-styles-graphql-grpc-webhooks.md))
- Running the development server in production. `uvicorn --reload` and Django's `runserver` are for development. Django's own docs warn that `runserver` has not been audited for security. Use a production server (uvicorn or gunicorn behind a proxy) and, in Django, set `DEBUG = False` and a real `ALLOWED_HOSTS`. ([Python back ends: FastAPI and Django](../09-back-end/01-servers-and-apis/07-python-back-ends-fastapi-and-django.md))
- Blocking calls inside an `async def` FastAPI route. As in Node, a long synchronous call (a slow query with a blocking driver) stalls the event loop for every request. A plain `def` route runs in a thread pool, which is safe for blocking code. ([Python back ends: FastAPI and Django](../09-back-end/01-servers-and-apis/07-python-back-ends-fastapi-and-django.md))
- Checking permissions only in the front end. The server never sees the hidden button, only the request, so every rule must also run in the API. ([Authentication vs authorization](../09-back-end/02-auth/01-authentication-vs-authorization.md))
- Reading the role from the request body or a header the client controls (`{"role": "admin"}`). Take the role from the verified token or the server-side session, or look it up in the database. ([Authentication vs authorization](../09-back-end/02-auth/01-authentication-vs-authorization.md))
- Returning 403 for everything, or 200 with an error message in the body. Clients, monitoring and caches all rely on the status code. ([Authentication vs authorization](../09-back-end/02-auth/01-authentication-vs-authorization.md))
- Believing a JWT is encrypted. Decoding needs no key, as Example 2 shows. Keep passwords, card numbers and similar data out of the payload. ([Sessions, cookies and JWT](../09-back-end/02-auth/02-sessions-cookies-and-jwt.md))
- Long-lived JWTs with no way to revoke them. Use an access token of minutes plus a refresh token that the server stores. ([Sessions, cookies and JWT](../09-back-end/02-auth/02-sessions-cookies-and-jwt.md))
- Storing a session id or token in `localStorage` for convenience. One XSS bug lets an attacker copy it. Prefer an `HttpOnly` cookie. ([Sessions, cookies and JWT](../09-back-end/02-auth/02-sessions-cookies-and-jwt.md))
- Using OAuth alone as a login. An access token says an app may call an API, not who is at the keyboard. Use OIDC and verify the ID token. ([OAuth and SSO](../09-back-end/02-auth/03-oauth-and-sso.md))
- Skipping `state`, or accepting any `redirect_uri`. Register exact redirect URIs with the provider and always check `state`. ([OAuth and SSO](../09-back-end/02-auth/03-oauth-and-sso.md))
- Putting the client secret in front-end code. A browser or mobile app can't keep a secret, so it uses PKCE with no secret. ([OAuth and SSO](../09-back-end/02-auth/03-oauth-and-sso.md))
- Fixing the error with `Access-Control-Allow-Origin: *` on an API that uses cookies. Browsers refuse `*` together with credentials, and reflecting any `Origin` back is worse: it lets every site read logged-in responses. ([CORS and same origin](../09-back-end/02-auth/04-cors-and-same-origin.md))
- Trying to fix CORS in the front end. The fix is always a response header from the server. A dev proxy (for example Vite's `server.proxy`) avoids the issue in development because the browser then sees one origin. ([CORS and same origin](../09-back-end/02-auth/04-cors-and-same-origin.md))
- Registering `cors()` after the routes, or letting `OPTIONS` hit an auth check. The preflight carries no credentials, so it must be answered before authentication runs. ([CORS and same origin](../09-back-end/02-auth/04-cors-and-same-origin.md))
- A job that is not idempotent, such as "add 10 to the balance". A retry after a crash adds 10 twice. Store what the final state should be, or record the job id as done. ([Background jobs](../09-back-end/03-api-quality/01-background-jobs.md))
- Retrying forever, or retrying errors that can't succeed (a malformed email address). Set a maximum, back off, and send permanent failures to the DLQ. ([Background jobs](../09-back-end/03-api-quality/01-background-jobs.md))
- Putting large data or secrets in the job. Store ids and look the data up in the worker; the queue is not a database. ([Background jobs](../09-back-end/03-api-quality/01-background-jobs.md))
- Tests that only check the status code. A 200 with a wrong or missing field passes. Assert on the body, or validate it against a schema. ([Testing and documenting APIs](../09-back-end/03-api-quality/02-testing-and-documenting-apis.md))
- Tests that share data and depend on order, such as the second test expecting the id the first one created. Reset the data before each test or create what each test needs. ([Testing and documenting APIs](../09-back-end/03-api-quality/02-testing-and-documenting-apis.md))
- Docs that describe only success. Callers write error handling from your reference, so list the 400, 401, 403, 404 and 429 responses with their body shape. ([Testing and documenting APIs](../09-back-end/03-api-quality/02-testing-and-documenting-apis.md))

## Databases, SQL and Postgres

- Treating the database as a file you read whole. Loading all of `order_items` (1689 rows here, millions in a real store) into your program to filter it there wastes time and memory. Ask the database for the rows you need with a `WHERE`. ([What a database is](../10-databases-sql-and-postgres/01-database-basics/01-what-a-database-is.md))
- Assuming "relational" means "slow" or "NoSQL" means "faster". A single Postgres server handles far more than most applications need. Choose another family when you can name the requirement (a graph traversal, a huge key-value workload), not because it sounds scalable. ([What a database is](../10-databases-sql-and-postgres/01-database-basics/01-what-a-database-is.md))
- `WHERE phone = NULL` returns no rows and no error. Write `WHERE phone IS NULL`. A related trap: `WHERE province <> 'ON'` also drops rows where `province` is `NULL`, because `NULL <> 'ON'` is unknown. ([The relational model](../10-databases-sql-and-postgres/01-database-basics/02-the-relational-model.md))
- Using a value that changes as the key. An email address or a name looks unique but people change both. Use a stable id (`customer_id`) as the primary key and keep the email as an ordinary column. ([The relational model](../10-databases-sql-and-postgres/01-database-basics/02-the-relational-model.md))
- Assuming rows have an order. Without `ORDER BY`, the order of rows from a table is not defined, even if it looked sorted the last time you ran the query. ([The relational model](../10-databases-sql-and-postgres/01-database-basics/02-the-relational-model.md))
- A statement without a semicolon. The prompt changes from `shop=>` to `shop->` and waits for more input. Type `;` to finish it, or press Ctrl+C to cancel. ([Postgres and psql](../10-databases-sql-and-postgres/01-database-basics/03-postgres-and-psql.md))
- Confusing the server being off with a wrong password. "Connection refused" means nothing is listening on that host and port (in WSL, run `sudo service postgresql start`). "Password authentication failed" means the server is running and rejected the login. ([Postgres and psql](../10-databases-sql-and-postgres/01-database-basics/03-postgres-and-psql.md))
- Running a copied script on the wrong database. `shop.sql` begins with `DROP TABLE IF EXISTS... CASCADE`, so it deletes tables of the same names. Check the prompt (or `\conninfo`) before `\i`. ([Postgres and psql](../10-databases-sql-and-postgres/01-database-basics/03-postgres-and-psql.md))
- `LIMIT` without `ORDER BY` returns some rows, not the first rows. The same query can return different rows after an update or on another server. Always sort when you cut. ([SELECT, WHERE and ORDER BY](../10-databases-sql-and-postgres/02-querying/01-select-where-and-order-by.md))
- `SELECT *` in application code. It returns every column, so adding a column to the table changes the result, and it hides which columns the code really needs. Name the columns. ([SELECT, WHERE and ORDER BY](../10-databases-sql-and-postgres/02-querying/01-select-where-and-order-by.md))
- `price BETWEEN 50 AND 20` returns no rows, because the lower bound must come first. Dates are the usual trap: `BETWEEN '2026-01-01' AND '2026-01-31'` on a timestamp column drops everything after midnight on January 31. Use `>=` and `<`. ([SELECT, WHERE and ORDER BY](../10-databases-sql-and-postgres/02-querying/01-select-where-and-order-by.md))
- `WHERE email = NULL` is never true, so it returns zero rows and no error. Write `IS NULL`. In the shop data it finds 22 customers with no email. ([NULL and three-valued logic](../10-databases-sql-and-postgres/02-querying/02-null-and-three-valued-logic.md))
- `COALESCE(x, 0)` can hide a real difference. A missing price replaced by 0 makes an average smaller and a free item indistinguishable from an unknown one. Decide what "missing" means before you replace it. ([NULL and three-valued logic](../10-databases-sql-and-postgres/02-querying/02-null-and-three-valued-logic.md))
- `NOT IN` with a subquery on a column that allows `NULL`. A single `NULL` in the list empties the result (Example 2). Prefer `NOT EXISTS`. ([NULL and three-valued logic](../10-databases-sql-and-postgres/02-querying/02-null-and-three-valued-logic.md))
- Putting an aggregate in `WHERE`, such as `WHERE count(*) > 5`. `WHERE` runs before groups exist, so Postgres rejects it. Move the test to `HAVING`. ([Aggregates, GROUP BY and HAVING](../10-databases-sql-and-postgres/02-querying/03-aggregates-group-by-and-having.md))
- `avg` ignores `NULL`, so it is the average of the known values, not of all rows. If missing means zero, say so with `avg(COALESCE(x, 0))`, and decide that on purpose. ([Aggregates, GROUP BY and HAVING](../10-databases-sql-and-postgres/02-querying/03-aggregates-group-by-and-having.md))
- `count(*)` after a join counts joined rows, not the entities you meant. Counting orders through `order_items` counts items; use `count(DISTINCT order_id)`, as the [joins lesson](../10-databases-sql-and-postgres/02-querying/04-joins.md) shows. ([Aggregates, GROUP BY and HAVING](../10-databases-sql-and-postgres/02-querying/03-aggregates-group-by-and-having.md))
- A `WHERE` filter on the right table turns a left join back into an inner join. A padded row has `NULL` in every right-hand column, so a test such as `o.status = 'refunded'` is not true for it and the row is removed. To count refunded orders per province and still list provinces with none, put the filter in `ON`. ([Joins](../10-databases-sql-and-postgres/02-querying/04-joins.md))
- Joining a "one" row to "many" rows repeats the one row, and aggregates then count or add the repeats. Joining `orders` to `order_items` gives 1689 rows for 900 orders, so `count(*)` counts items, not orders. ([Joins](../10-databases-sql-and-postgres/02-querying/04-joins.md))
- A lost join condition. In `FROM a, b` the comma is a cross join, so `customers, orders` with no `WHERE` returns 200 times 900 rows. ([Joins](../10-databases-sql-and-postgres/02-querying/04-joins.md))
- A scalar subquery that returns several rows. `price = (SELECT price FROM products WHERE category = 'Books')` fails with "more than one row returned by a subquery used as an expression". Aggregate it, or use `IN`. ([Subqueries](../10-databases-sql-and-postgres/02-querying/05-subqueries.md))
- Forgetting the correlation. In `EXISTS (SELECT 1 FROM orders WHERE status = 'refunded')` nothing links the inner query to the outer row, so it is true for every customer or for none. Check that the inner query mentions the outer alias. ([Subqueries](../10-databases-sql-and-postgres/02-querying/05-subqueries.md))
- `NOT IN (SELECT col...)` when `col` can be `NULL`. One `NULL` makes the result empty. Use `NOT EXISTS`. ([Subqueries](../10-databases-sql-and-postgres/02-querying/05-subqueries.md))
- A recursive member with no end. If the data can contain a cycle, add the `CYCLE` clause, or a depth limit such as `WHERE c.depth < 10` in the recursive member. Replacing `UNION ALL` with `UNION` also stops a cycle here, because a repeated row is dropped, but it fails as soon as a column such as `depth` differs on each visit. ([CTEs and recursive queries](../10-databases-sql-and-postgres/02-querying/06-ctes-and-recursive-queries.md))
- Treating a CTE as a stored table. It exists only inside its statement, and if the main query uses it twice, it may be computed twice unless you write `AS MATERIALIZED`. ([CTEs and recursive queries](../10-databases-sql-and-postgres/02-querying/06-ctes-and-recursive-queries.md))
- Filtering a window function in `WHERE`. ([Window functions](../10-databases-sql-and-postgres/02-querying/07-window-functions.md))
- A missing or incomplete `ORDER BY` in `OVER`. Without it, `row_number` and `lag` depend on whatever order the rows arrive in, and the answer can change between runs. Add a tie-breaker (a unique column) when the sort column can repeat. ([Window functions](../10-databases-sql-and-postgres/02-querying/07-window-functions.md))
- Mismatched columns. The next two queries fail with "UNION types integer and text cannot be matched" and "each UNION query must have the same number of columns". Fix them by casting (`customer_id::text`) or by selecting the same number of columns. ([Set operations and CASE](../10-databases-sql-and-postgres/02-querying/08-set-operations-and-case.md))
- A missing `ELSE` returns `NULL`, and `sum()` of only `NULL` values is `NULL`, not 0. On the 900 orders, `sum(CASE WHEN status = 'nonsense' THEN 1 END)` is `NULL`, while the same expression with `ELSE 0` is 0. Use `ELSE 0` for counts. ([Set operations and CASE](../10-databases-sql-and-postgres/02-querying/08-set-operations-and-case.md))
- Using `timestamp` for real moments. Two servers in different zones will store different clock labels for the same moment, and nothing says which zone the label meant. Store events as `timestamptz`, store a plain `date` for calendar days, and keep the zone name (`America/Toronto`, not a fixed `-05`) when a user's local time matters, because only a named zone follows daylight saving. ([Text, dates and times](../10-databases-sql-and-postgres/02-querying/09-text-dates-and-times.md))
- `BETWEEN` on timestamps. `created_at BETWEEN '2026-03-01' AND '2026-03-31'` stops at midnight at the start of 31 March and misses almost the whole last day. Use `>= '2026-03-01' AND < '2026-04-01'`. ([Text, dates and times](../10-databases-sql-and-postgres/02-querying/09-text-dates-and-times.md))
- `LIKE` with `%` or `_` in the data. To match a literal percent sign, escape it: `'100%' LIKE '100\%'` is true, since a backslash is the default escape character. ([Text, dates and times](../10-databases-sql-and-postgres/02-querying/09-text-dates-and-times.md))
- Money in `real` or `double precision`. Sums drift by tiny fractions, and `=` comparisons fail, as the first box showed. Use `numeric(12,2)`, or store integer cents. ([Data types and constraints](../10-databases-sql-and-postgres/03-schema-design/01-data-types-and-constraints.md))
- `ON DELETE CASCADE` on everything. Deleting one `customers` row can silently delete their orders, invoices and payments. Use `CASCADE` only for rows that mean nothing without the parent (order lines), and `RESTRICT` where history matters. ([Data types and constraints](../10-databases-sql-and-postgres/03-schema-design/01-data-types-and-constraints.md))
- Skipping `NOT NULL`. A nullable column that is always filled in practice will eventually hold a `NULL`, and every query that touches it then needs `NULL` handling. Make columns `NOT NULL` unless "unknown" is a real answer. ([Data types and constraints](../10-databases-sql-and-postgres/03-schema-design/01-data-types-and-constraints.md))
- `UPDATE` or `DELETE` with no `WHERE`, or with a `WHERE` that matches more than you thought (`OR` without parentheses). Run the `SELECT` form first, compare the row count, and in a shared database take a backup or work inside a transaction. ([Creating and changing tables and data](../10-databases-sql-and-postgres/03-schema-design/02-creating-and-changing-tables-and-data.md))
- `INSERT` without a column list, such as `INSERT INTO t VALUES (1, 'x')`. It works until someone adds or reorders a column, then it writes into the wrong columns or fails. Always list the columns. ([Creating and changing tables and data](../10-databases-sql-and-postgres/03-schema-design/02-creating-and-changing-tables-and-data.md))
- `DROP COLUMN` or a rename that ships before the code that uses it. Deploy code that no longer uses the column first, then drop it in a later migration. ([Creating and changing tables and data](../10-databases-sql-and-postgres/03-schema-design/02-creating-and-changing-tables-and-data.md))
- Storing a list in one column, such as `courses.student_ids` holding `'1,2,5'`. You can't join on it, constrain it or index it well. Use a junction table. ([Modelling relationships and ER diagrams](../10-databases-sql-and-postgres/03-schema-design/03-modelling-relationships-and-er-diagrams.md))
- Putting the foreign key on the wrong side. The key goes on the "many" side. If `instructors` had a `course_id`, an instructor could teach only one course. ([Modelling relationships and ER diagrams](../10-databases-sql-and-postgres/03-schema-design/03-modelling-relationships-and-er-diagrams.md))
- A junction table with a surrogate `id` and no unique pair. Without a unique constraint on the two foreign keys, duplicate pairings are allowed. Use the pair as the primary key, or add `UNIQUE (student_id, course_id)`. ([Modelling relationships and ER diagrams](../10-databases-sql-and-postgres/03-schema-design/03-modelling-relationships-and-er-diagrams.md))
- Denormalizing before measuring. A copied column (`orders.customer_city`) is easy to add and hard to keep correct. Normalize first, add an index, and look at the [query plan](../10-databases-sql-and-postgres/04-postgres-in-depth/02-explain-and-query-plans.md) before copying data. ([Normalization and denormalization](../10-databases-sql-and-postgres/03-schema-design/04-normalization-and-denormalization.md))
- Over-splitting. Putting `city` and `province` in their own tables for an address that is only ever shown whole adds joins and no safety. Normalize facts that change independently or repeat a lot. ([Normalization and denormalization](../10-databases-sql-and-postgres/03-schema-design/04-normalization-and-denormalization.md))
- A denormalized copy with no plan to refresh it. For every copy or cache, write down what updates it and how stale it may be. ([Normalization and denormalization](../10-databases-sql-and-postgres/03-schema-design/04-normalization-and-denormalization.md))
- "index everything". Each index is extra storage and each `INSERT`, `UPDATE` and `DELETE` must update every index on the table. In our 100,000-row table the heap is 5120 kB and one index on `customer_id` with `INCLUDE (amount)` adds 2224 kB. Keep indexes that a real query uses, and drop the rest (`pg_stat_user_indexes.idx_scan` counts uses). ([Indexes](../10-databases-sql-and-postgres/04-postgres-in-depth/01-indexes.md))
- Foreign keys are not indexed automatically. Postgres indexes the primary key side only. A join or an `ON DELETE` check on `orders.customer_id` scans the whole `orders` table until you add `CREATE INDEX ON orders (customer_id)`. ([Indexes](../10-databases-sql-and-postgres/04-postgres-in-depth/01-indexes.md))
- `CREATE INDEX` blocks writes to the table while it builds. On a live table use `CREATE INDEX CONCURRENTLY`, which takes longer, can't run inside a transaction block, and leaves an `INVALID` index to drop if it fails. ([Indexes](../10-databases-sql-and-postgres/04-postgres-in-depth/01-indexes.md))
- Running `EXPLAIN ANALYZE` on a `DELETE` or `UPDATE` really changes the data. Use `BEGIN; EXPLAIN ANALYZE...; ROLLBACK;`. ([EXPLAIN and query plans](../10-databases-sql-and-postgres/04-postgres-in-depth/02-explain-and-query-plans.md))
- Comparing `cost` numbers between different queries, or reading them as time. Compare estimated and actual rows, and use the `actual time` and `Buffers` fields from `EXPLAIN (ANALYZE, BUFFERS)` for time and I/O. ([EXPLAIN and query plans](../10-databases-sql-and-postgres/04-postgres-in-depth/02-explain-and-query-plans.md))
- Testing on a tiny table. With 100 rows the planner correctly prefers a `Seq Scan` and your new index looks useless. Test with data of production size, or generate it as in this lesson. ([EXPLAIN and query plans](../10-databases-sql-and-postgres/04-postgres-in-depth/02-explain-and-query-plans.md))
- Forgetting `COMMIT`. A session with an open `BEGIN` holds its changes private and keeps locks and old row versions alive. An idle-in-transaction connection can block other sessions and stop `VACUUM` from cleaning up. In app code, use the driver's transaction block so commit or rollback always happens. ([Transactions and ACID](../10-databases-sql-and-postgres/04-postgres-in-depth/03-transactions-and-acid.md))
- Believing a transaction makes a read-modify-write safe. Reading a balance into your app, adding to it and writing it back inside a transaction can still lose another session's update. Isolation and locking, next, explain when. ([Transactions and ACID](../10-databases-sql-and-postgres/04-postgres-in-depth/03-transactions-and-acid.md))
- Doing slow work inside a transaction, such as an HTTP call. The transaction stays open for the duration, holding locks. Do the slow work first, then open the transaction for the quick writes. ([Transactions and ACID](../10-databases-sql-and-postgres/04-postgres-in-depth/03-transactions-and-acid.md))
- Read-modify-write in the application under `READ COMMITTED`. The code looks right and passes tests with one user. Move the arithmetic into SQL, add `FOR UPDATE`, or raise the isolation level and retry. ([Isolation, locking and MVCC](../10-databases-sql-and-postgres/04-postgres-in-depth/04-isolation-locking-and-mvcc.md))
- Raising isolation without a retry loop. `REPEATABLE READ` and `SERIALIZABLE` abort transactions on conflict by design. If the app shows that error to a user instead of retrying, you have traded wrong data for failed requests. ([Isolation, locking and MVCC](../10-databases-sql-and-postgres/04-postgres-in-depth/04-isolation-locking-and-mvcc.md))
- Believing `SELECT` takes locks that block writers. In Postgres, plain reads take no row locks. Only `FOR UPDATE`, `FOR SHARE` and similar clauses do. ([Isolation, locking and MVCC](../10-databases-sql-and-postgres/04-postgres-in-depth/04-isolation-locking-and-mvcc.md))
- Running the app as the table owner or as a superuser. Owners and superusers skip RLS, and either can drop tables. Create a separate migrator role that owns the tables and an app role that doesn't, and test policies as the app role, not as `postgres`. ([Roles, privileges and row-level security](../10-databases-sql-and-postgres/04-postgres-in-depth/05-roles-privileges-and-row-level-security.md))
- Enabling RLS and adding no policy. The table then returns zero rows to everyone but the owner, which looks like an empty table. Add policies for each command the role needs (`SELECT`, `INSERT`, `UPDATE`, `DELETE`), and add `WITH CHECK` so users can't insert rows they couldn't read. ([Roles, privileges and row-level security](../10-databases-sql-and-postgres/04-postgres-in-depth/05-roles-privileges-and-row-level-security.md))
- `GRANT ALL` and `PUBLIC`. Every role is a member of `PUBLIC`, so a grant to `PUBLIC` reaches everyone. Grant the specific privileges to a specific role, and read the result back with `\dp orders` in `psql`. ([Roles, privileges and row-level security](../10-databases-sql-and-postgres/04-postgres-in-depth/05-roles-privileges-and-row-level-security.md))
- Expecting a materialized view to stay current. It shows the data as of the last refresh. If a dashboard must be live, use a plain view or an index on the base tables, and say how old the data is where it is displayed. ([Views, functions and triggers](../10-databases-sql-and-postgres/04-postgres-in-depth/06-views-functions-and-triggers.md))
- A `BEFORE` trigger that forgets `RETURN NEW`. Returning `NULL` silently cancels the write, so rows seem to vanish with no error. In an `AFTER` trigger the return value is ignored. ([Views, functions and triggers](../10-databases-sql-and-postgres/04-postgres-in-depth/06-views-functions-and-triggers.md))
- A trigger that updates the same table it fires on. The change fires the trigger again, and an unbounded loop ends in a "stack depth limit exceeded" error. Change `NEW` in a `BEFORE` trigger instead of running a new `UPDATE`. ([Views, functions and triggers](../10-databases-sql-and-postgres/04-postgres-in-depth/06-views-functions-and-triggers.md))
- `->` returns JSON and `->>` returns text. `WHERE attrs->'colour' = 'black'` compares a JSON value with a text literal and fails or never matches. Use `->>` for text comparison, or `@>`. ([JSONB and full-text search](../10-databases-sql-and-postgres/04-postgres-in-depth/07-jsonb-and-full-text-search.md))
- A full-text query whose configuration differs from the index. `to_tsvector('english', col)` in the index and `to_tsvector(col)` in the query use different configurations, so the planner can't use the index. Use the same two-argument form everywhere, or a generated column as above. ([JSONB and full-text search](../10-databases-sql-and-postgres/04-postgres-in-depth/07-jsonb-and-full-text-search.md))
- Putting everything in one JSONB column. You lose type checks, foreign keys and simple statistics, and every query needs casts like `(attrs->>'price')::numeric`. Keep the stable fields as columns. ([JSONB and full-text search](../10-databases-sql-and-postgres/04-postgres-in-depth/07-jsonb-and-full-text-search.md))
- Believing replicas are backups. A replica copies every change, including `DROP TABLE` and the bad `DELETE`, within seconds. Replicas protect against hardware failure; backups with PITR protect against mistakes. ([Backups, replication and pooling](../10-databases-sql-and-postgres/04-postgres-in-depth/08-backups-replication-and-pooling.md))
- Never testing a restore. A backup that is corrupt, incomplete or missing a role shows this only when you need it. Schedule a restore into a scratch database and run a count query. ([Backups, replication and pooling](../10-databases-sql-and-postgres/04-postgres-in-depth/08-backups-replication-and-pooling.md))
- Using session features through a transaction pooler, such as `SET search_path` on login or session advisory locks. The next transaction may run on another connection that never saw the `SET`. Set it per transaction (`SET LOCAL`) or in the role's settings. ([Backups, replication and pooling](../10-databases-sql-and-postgres/04-postgres-in-depth/08-backups-replication-and-pooling.md))
- Building SQL with f-strings, `+`, template literals or `"..." % value`. The last one is the sneakiest because it looks like a placeholder. `execute("... = %s" % email)` formats the string first; `execute("... = %s", (email,))` passes the value to the driver. Escaping quotes by hand is not a fix either; use the driver's parameters. ([SQL from code and SQL injection](../10-databases-sql-and-postgres/05-databases-in-apps/01-sql-from-code-and-sql-injection.md))
- Opening a new connection per request, or never returning one. The first is slow and can hit Postgres's connection limit; the second drains the pool. Use a pool, and use `with` or `try`/`finally` so the connection always goes back. ([SQL from code and SQL injection](../10-databases-sql-and-postgres/05-databases-in-apps/01-sql-from-code-and-sql-injection.md))
- Putting the connection string in the source. It holds the password, and a pushed secret has to be treated as leaked. Read `DATABASE_URL` from the environment. ([SQL from code and SQL injection](../10-databases-sql-and-postgres/05-databases-in-apps/01-sql-from-code-and-sql-injection.md))
- Assuming a loop over ORM objects is cheap. Lazy loading hides the queries. Turn on query logging or count statements in tests, and use eager loading when you read a relationship for every row. ([ORMs and migrations](../10-databases-sql-and-postgres/05-databases-in-apps/02-orms-and-migrations.md))
- Editing an old migration to "fix" it after it has been applied, or running schema changes by hand on production. The migration history then no longer describes the real database. Add a new migration instead. ([ORMs and migrations](../10-databases-sql-and-postgres/05-databases-in-apps/02-orms-and-migrations.md))
- Running `downgrade` on production as an undo button. Dropping a column also drops its data, and a down migration can't bring it back. Take a backup first, and prefer a new forward migration. ([ORMs and migrations](../10-databases-sql-and-postgres/05-databases-in-apps/02-orms-and-migrations.md))
- Choosing NoSQL because "relational doesn't scale". A single well-indexed Postgres server handles far more than most apps ever need. Move when you can name the specific limit you hit. ([NoSQL databases](../10-databases-sql-and-postgres/05-databases-in-apps/03-nosql-databases.md))
- Treating schema-on-read as "no schema". The structure still exists, in your code. Without checks, old documents with the old shape pile up and every reader has to handle all of them. ([NoSQL databases](../10-databases-sql-and-postgres/05-databases-in-apps/03-nosql-databases.md))
- Using a document store for data that is really relational (users, orders, payments). You end up re-implementing joins and consistency in application code. ([NoSQL databases](../10-databases-sql-and-postgres/05-databases-in-apps/03-nosql-databases.md))
- Caching without an invalidation plan. A value cached for an hour is wrong for an hour after an update. Delete the key on writes, and keep TTLs short for data that changes. ([Redis and caching](../10-databases-sql-and-postgres/05-databases-in-apps/04-redis-and-caching.md))
- Treating Redis as the only copy of important data. Memory is limited, eviction deletes keys, and a restart can lose recent writes unless persistence is configured. Postgres stays the source of truth. ([Redis and caching](../10-databases-sql-and-postgres/05-databases-in-apps/04-redis-and-caching.md))
- Caching a miss as a failure. If the user doesn't exist and you query Postgres every time, attackers can flood the database with random ids. Cache the "not found" result for a short time. ([Redis and caching](../10-databases-sql-and-postgres/05-databases-in-apps/04-redis-and-caching.md))

## Data engineering and data science

- Running heavy reports on the production OLTP database "because it already has the data". One long scan slows checkout. The fix is a [read replica](../10-databases-sql-and-postgres/04-postgres-in-depth/08-backups-replication-and-pooling.md) for small teams, or a warehouse once reports get big. ([OLTP vs OLAP and warehouses](../11-data-engineering-and-data-science/01-data-engineering/01-oltp-vs-olap-and-warehouses.md))
- Treating the warehouse as a backup of the application database. A warehouse is reshaped, delayed by the pipeline and may drop columns, so it can't restore the app. ([OLTP vs OLAP and warehouses](../11-data-engineering-and-data-science/01-data-engineering/01-oltp-vs-olap-and-warehouses.md))
- Mixing grains. If a fact table holds both sale lines and monthly targets, `sum(amount)` double counts. One table, one grain. ([Star schemas and dimensional modelling](../11-data-engineering-and-data-science/01-data-engineering/02-star-schemas-and-dimensional-modelling.md))
- Summing a measure that does not add across a dimension, such as a balance or a unit price. Average it or use the last value instead. ([Star schemas and dimensional modelling](../11-data-engineering-and-data-science/01-data-engineering/02-star-schemas-and-dimensional-modelling.md))
- Joining a type 2 dimension on the business key alone. Each customer then matches several rows and the fact rows multiply. Join on the surrogate key, or add the date range to the condition. ([Star schemas and dimensional modelling](../11-data-engineering-and-data-science/01-data-engineering/02-star-schemas-and-dimensional-modelling.md))
- A watermark on a timestamp that can arrive late. If a row dated June 3 shows up on June 5, a watermark of June 4 skips it forever. Re-read a few days before the watermark and make the load idempotent, or use an ingestion time that the pipeline sets. ([ETL and ELT pipelines](../11-data-engineering-and-data-science/01-data-engineering/03-etl-and-elt-pipelines.md))
- Transforming staging in place. Keep staging raw, so you can rebuild the other layers. ([ETL and ELT pipelines](../11-data-engineering-and-data-science/01-data-engineering/03-etl-and-elt-pipelines.md))
- Using `COPY` when you mean `\copy`. `COPY 'sales.csv'` looks for the file on the database server, which may be a different machine, and your role may not be allowed to read files there. Use `\copy` from `psql`. ([Loading data into Postgres](../11-data-engineering-and-data-science/01-data-engineering/04-loading-data-into-postgres.md))
- Loading straight into the final table. One bad value aborts the load, and a rerun inserts duplicates. Load into staging, then upsert. ([Loading data into Postgres](../11-data-engineering-and-data-science/01-data-engineering/04-loading-data-into-postgres.md))
- An upsert that overwrites newer data with older. If an old file is replayed, `DO UPDATE` rewrites good rows. Add `WHERE target.updated_at < EXCLUDED.updated_at` to the `DO UPDATE` clause when files can arrive out of order. ([Loading data into Postgres](../11-data-engineering-and-data-science/01-data-engineering/04-loading-data-into-postgres.md))
- Choosing streaming because "real time" sounds better. If the report is read once a morning, a nightly batch is simpler and cheaper. ([Batch and streaming](../11-data-engineering-and-data-science/01-data-engineering/05-batch-and-streaming.md))
- Assuming a topic is ordered. Order holds inside one partition only, so events that must stay in order need the same key. ([Batch and streaming](../11-data-engineering-and-data-science/01-data-engineering/05-batch-and-streaming.md))
- Trusting "exactly-once" in a product description. Ask where the effect is recorded and what happens on a crash between work and commit. ([Batch and streaming](../11-data-engineering-and-data-science/01-data-engineering/05-batch-and-streaming.md))
- A plain `INSERT` in a task. The first retry doubles the day. On the `warehouse` database, inserting the day 20250103 twice gives 2 rows and 189.48 of revenue instead of 1 row and 94.74. Use delete-insert or `MERGE`. ([Orchestration and idempotent jobs](../11-data-engineering-and-data-science/01-data-engineering/06-orchestration-and-idempotent-jobs.md))
- `WHERE order_date = current_date` inside a task. A backfill of last week then loads today seven times. Pass the logical date in as a parameter. ([Orchestration and idempotent jobs](../11-data-engineering-and-data-science/01-data-engineering/06-orchestration-and-idempotent-jobs.md))
- An upsert that only updates some columns. If the source later changes or removes a row, the old values or the stale row stay. Decide whether a partition is replaced as a whole (delete-insert) or merged by key. ([Orchestration and idempotent jobs](../11-data-engineering-and-data-science/01-data-engineering/06-orchestration-and-idempotent-jobs.md))
- Hard-coding table names (`from analytics.stg_orders`) instead of `ref()`. dbt then cannot see the dependency, so it may run models in the wrong order and the lineage graph has gaps. ([dbt and SQL transformations](../11-data-engineering-and-data-science/01-data-engineering/07-dbt-and-sql-transformations.md))
- An incremental model with no `unique_key`, or a filter that skips late-arriving rows. A rerun appends duplicates, and rows that arrive a day late are never picked up. Use a key, and filter with some overlap. ([dbt and SQL transformations](../11-data-engineering-and-data-science/01-data-engineering/07-dbt-and-sql-transformations.md))
- A passing test suite is not proof of correct data. The tests check only the rules you wrote. The mart above would pass even if every amount were 100 times too large. ([dbt and SQL transformations](../11-data-engineering-and-data-science/01-data-engineering/07-dbt-and-sql-transformations.md))
- Opening a CSV and trusting the column types. A zip code `02134` becomes the number 2134, and a column of dates may be read as text. Give the reader an explicit schema, or use a format that stores one. ([File formats and columnar storage](../11-data-engineering-and-data-science/01-data-engineering/08-file-formats-and-columnar-storage.md))
- Many tiny Parquet files. Each file has a footer to open and read, so a million 10 KB files is much slower than a hundred 100 MB ones. Write fewer, larger files, and partition by a low-cardinality column. ([File formats and columnar storage](../11-data-engineering-and-data-science/01-data-engineering/08-file-formats-and-columnar-storage.md))
- `SELECT *` on a columnar file. It reads every column and removes the advantage. Name the columns you need. ([File formats and columnar storage](../11-data-engineering-and-data-science/01-data-engineering/08-file-formats-and-columnar-storage.md))
- A check that passes because it tests nothing. `WHERE x = NULL` is never true, and an inner join to a dimension hides orphans instead of finding them. Always test a new check against data you know is bad, as in Example 2. ([Data quality](../11-data-engineering-and-data-science/01-data-engineering/09-data-quality.md))
- Checking only after publishing. If the check runs on the live table, users have already seen the bad data. Check in staging, then publish. ([Data quality](../11-data-engineering-and-data-science/01-data-engineering/09-data-quality.md))
- Alert fatigue. A check that fails every day for a known reason gets ignored, and then the real failure is ignored too. Fix the cause or remove the check; use warnings for rules you are still tuning. ([Data quality](../11-data-engineering-and-data-science/01-data-engineering/09-data-quality.md))
- "lake" without governance becomes a data swamp: files nobody can find, trust or delete. A catalog (names, owners, schemas) and quality checks matter more than the storage choice. ([Lakes, lakehouses and cloud warehouses](../11-data-engineering-and-data-science/01-data-engineering/10-lakes-lakehouses-and-cloud-warehouses.md))
- Starting a large cloud cluster or warehouse and leaving it running. Compute bills while it runs. Set auto-suspend and a budget alert, and shut down what you create in labs. ([Lakes, lakehouses and cloud warehouses](../11-data-engineering-and-data-science/01-data-engineering/10-lakes-lakehouses-and-cloud-warehouses.md))
- Reporting an average for skewed data. Use the median plus p95 or p99, and say which one you used. ([Statistics for data work](../11-data-engineering-and-data-science/02-data-science-and-ml/01-statistics-for-data-work.md))
- Reading a correlation as a cause. Ask what third variable could drive both, then look for an experiment. ([Statistics for data work](../11-data-engineering-and-data-science/02-data-science-and-ml/01-statistics-for-data-work.md))
- Trusting a sample you did not choose. A survey of app users says nothing about people who left the app, and a log that only records successful requests hides the failures. ([Statistics for data work](../11-data-engineering-and-data-science/02-data-science-and-ml/01-statistics-for-data-work.md))
- `count(*)` where you need `count(DISTINCT user_id)`. Ten page views from one user then count as ten active users. ([Analytics in SQL: cohorts, funnels and retention](../11-data-engineering-and-data-science/02-data-science-and-ml/02-analytics-sql-cohorts-funnels-retention.md))
- Grouping by day in the wrong time zone, or comparing a half-finished current month with full months. Exclude the incomplete period, as the retention query does with its `WHERE` on the cohort month. ([Analytics in SQL: cohorts, funnels and retention](../11-data-engineering-and-data-science/02-data-science-and-ml/02-analytics-sql-cohorts-funnels-retention.md))
- A funnel that counts a purchase from a user who never viewed a page. Require the steps in order, as in Example 2. ([Analytics in SQL: cohorts, funnels and retention](../11-data-engineering-and-data-science/02-data-science-and-ml/02-analytics-sql-cohorts-funnels-retention.md))
- Stopping the test the moment the p-value dips under 0.05. Fix the sample size first, or use a method built for sequential looks. ([A/B testing](../11-data-engineering-and-data-science/02-data-science-and-ml/03-ab-testing.md))
- Reading "p = 0.03" as "a 97% chance B is better". The p-value assumes the null is true; it says how surprising the data is, not how likely each hypothesis is. ([A/B testing](../11-data-engineering-and-data-science/02-data-science-and-ml/03-ab-testing.md))
- A significant result that is too small to matter. With millions of users a 0.01-point lift is significant. Check the interval against the smallest change worth shipping. ([A/B testing](../11-data-engineering-and-data-science/02-data-science-and-ml/03-ab-testing.md))
- Jumping to a model before checking the data. Missing values, wrong units and duplicates teach the model the wrong rule. Look at the columns first, with the tools from the statistics lesson. ([What machine learning is](../11-data-engineering-and-data-science/02-data-science-and-ml/04-what-machine-learning-is.md))
- Skipping the baseline. Without "always predict the average", a number like 80% accuracy has no meaning. ([What machine learning is](../11-data-engineering-and-data-science/02-data-science-and-ml/04-what-machine-learning-is.md))
- Calling a model "intelligent". A trained line or forest is a fitted function. It repeats patterns in its examples, including the mistakes in them. ([What machine learning is](../11-data-engineering-and-data-science/02-data-science-and-ml/04-what-machine-learning-is.md))
- Fitting a scaler, imputer or feature selector on all the data before splitting. Put every step inside a `Pipeline` so it is fit on training rows only. ([Training, testing and metrics](../11-data-engineering-and-data-science/02-data-science-and-ml/05-training-testing-and-metrics.md))
- Tuning on the test set. Each time you look at test results and change something, the test set becomes a validation set. Keep one final test score. ([Training, testing and metrics](../11-data-engineering-and-data-science/02-data-science-and-ml/05-training-testing-and-metrics.md))
- Shuffling time-ordered data. For forecasting, train on the past and test on the future; a random split lets the model see the future. ([Training, testing and metrics](../11-data-engineering-and-data-science/02-data-science-and-ml/05-training-testing-and-metrics.md))
- Reading coefficients of unscaled features as importance. A weight depends on the feature's units. Scale first, or compare the effect of a standard deviation. ([Regression and classification with scikit-learn](../11-data-engineering-and-data-science/02-data-science-and-ml/06-regression-and-classification-with-scikit-learn.md))
- Assuming the more complex model wins. On Example 1, the forest was no better than a line. Start with a baseline and a linear or logistic model, and add complexity only when the validation score improves. ([Regression and classification with scikit-learn](../11-data-engineering-and-data-science/02-data-science-and-ml/06-regression-and-classification-with-scikit-learn.md))
- Trusting one score from a 100-row test set. Cross-validation (the previous lesson) shows how much the score moves. ([Regression and classification with scikit-learn](../11-data-engineering-and-data-science/02-data-science-and-ml/06-regression-and-classification-with-scikit-learn.md))
- Reaching for a neural network on a small table. A logistic regression or a forest is faster to train, easier to explain and often as accurate. Compare against them first. ([Neural networks and deep learning](../11-data-engineering-and-data-science/02-data-science-and-ml/07-neural-networks-and-deep-learning.md))
- A learning rate that is too high. The loss goes up or becomes `nan`. Lower it by a factor of 10 and try again. ([Neural networks and deep learning](../11-data-engineering-and-data-science/02-data-science-and-ml/07-neural-networks-and-deep-learning.md))
- Forgetting to scale the inputs. Networks train poorly when features have very different ranges, so use `StandardScaler` in the pipeline. ([Neural networks and deep learning](../11-data-engineering-and-data-science/02-data-science-and-ml/07-neural-networks-and-deep-learning.md))

## Security

- Security by obscurity. Hiding `/admin-7f3a` instead of checking roles protects nothing once the URL leaks. Assume the attacker knows how the system works; only secrets (keys, passwords) should stay secret. ([Security mindset and threat modelling](../12-security/01-web-security/01-security-mindset-and-threat-modelling.md))
- Trusting the client. A disabled button or a JavaScript check is a usability feature. The server repeats every check, because an attacker sends requests without your front end. ([Security mindset and threat modelling](../12-security/01-web-security/01-security-mindset-and-threat-modelling.md))
- Threat modelling once, at the start. Redo it when you add a feature that crosses a new boundary, such as a payment provider or file upload. ([Security mindset and threat modelling](../12-security/01-web-security/01-security-mindset-and-threat-modelling.md))
- Treating the Top 10 as a checklist you can finish. It names categories; passing it does not make an app secure. The [OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/) is the detailed standard. ([OWASP top 10](../12-security/01-web-security/02-owasp-top-10.md))
- Memorising the old order. Editions change: 2025 added A03 (supply chain) and A10 (exceptional conditions). Check the year when you cite a number. ([OWASP top 10](../12-security/01-web-security/02-owasp-top-10.md))
- Escaping by hand. Replacing `'` with `\'` misses encodings and differs between databases. Use the driver's placeholders. ([Injection and input validation](../12-security/01-web-security/03-injection-and-input-validation.md))
- Parameterizing values but concatenating identifiers. `ORDER BY ${req.query.sort}` cannot be a placeholder. Map the input through an allow-list (`{"name": "name", "date": "created_at"}`) and use the mapped value. ([Injection and input validation](../12-security/01-web-security/03-injection-and-input-validation.md))
- Validating on the client only. An attacker skips your form. Validate on the server, as in [validation and error handling](../09-back-end/01-servers-and-apis/05-validation-and-error-handling.md). ([Injection and input validation](../12-security/01-web-security/03-injection-and-input-validation.md))
- Thinking a CSP replaces escaping. It limits damage; the bug is still there. Also avoid `'unsafe-inline'` in `script-src`, which turns off the main protection. ([XSS, CSRF and browser security](../12-security/01-web-security/04-xss-csrf-and-browser-security.md))
- Storing a session token in `localStorage`. Any XSS reads it. A cookie with `HttpOnly` is out of reach of scripts. ([XSS, CSRF and browser security](../12-security/01-web-security/04-xss-csrf-and-browser-security.md))
- Relying on CORS to stop CSRF. CORS controls who may read responses, not who may send requests; the forged `POST` above still arrives. ([XSS, CSRF and browser security](../12-security/01-web-security/04-xss-csrf-and-browser-security.md))
- A fast hash such as SHA-256 or MD5 for passwords. They are built to be fast, so a GPU tests billions per second. Use Argon2id or bcrypt. ([Secure authentication](../12-security/01-web-security/05-secure-authentication.md))
- Leaking existence through timing or wording. "Email not found" on the reset page enumerates accounts as surely as the login page does. ([Secure authentication](../12-security/01-web-security/05-secure-authentication.md))
- Rolling your own session ids or tokens with `Math.random()` or `random`. Use a cryptographic source (`crypto.randomBytes`, Python's `secrets`). ([Secure authentication](../12-security/01-web-security/05-secure-authentication.md))
- Committing `.env` "just this once", or putting keys in front-end code. Anything shipped to a browser is public, and git history is permanent. Rotate the key. ([Secrets and dependency security](../12-security/01-web-security/06-secrets-and-dependency-security.md))
- Ignoring audit output because "it is only a dev dependency" or because there are 40 warnings. Sort by severity and whether the vulnerable code path is reachable, then fix the top items. ([Secrets and dependency security](../12-security/01-web-security/06-secrets-and-dependency-security.md))
- Using a version range like `^1.2.0` with no lockfile in CI. The build on Friday can differ from Thursday's. ([Secrets and dependency security](../12-security/01-web-security/06-secrets-and-dependency-security.md))
- Storing `sha256(password)`, even with a salt. It is fast to brute-force. Use Argon2id, scrypt, bcrypt or PBKDF2. ([Hashing and salts](../12-security/02-cryptography/01-hashing-and-salts.md))
- One fixed salt for all users, hard-coded in the source, in place of a random salt per user. The point of a salt is that every row differs. ([Hashing and salts](../12-security/02-cryptography/01-hashing-and-salts.md))
- Comparing tags or hashes with `==`. It can leak how many leading characters matched through timing. Use `hmac.compare_digest`. ([Hashing and salts](../12-security/02-cryptography/01-hashing-and-salts.md))
- A hard-coded nonce, or a nonce from a counter that resets after a restart. Use a random 12-byte value per message (or a counter that survives restarts). ([Symmetric encryption](../12-security/02-cryptography/02-symmetric-encryption.md))
- Encrypting with the key stored next to the data, such as in the same repository or database. The encryption then protects nothing. Keep keys in a secrets manager or key management service, and rotate them. ([Symmetric encryption](../12-security/02-cryptography/02-symmetric-encryption.md))
- Using a password directly as a key. Derive the key from the password with a KDF (see [Hashing and salts](../12-security/02-cryptography/01-hashing-and-salts.md)). ([Symmetric encryption](../12-security/02-cryptography/02-symmetric-encryption.md))
- Thinking "encrypting with the private key" is how signatures work. Use the signing API of the library; it handles hashing and padding for you. ([Public-key encryption and signatures](../12-security/02-cryptography/03-public-key-encryption-and-signatures.md))
- Trusting a public key you received over an unauthenticated channel. If an attacker swapped it, you encrypt to them. Public keys must be verified, by a certificate or by comparing a fingerprint. ([Public-key encryption and signatures](../12-security/02-cryptography/03-public-key-encryption-and-signatures.md))
- Sharing or committing a private key. Private keys never go in a repo, a chat message or a log. ([Public-key encryption and signatures](../12-security/02-cryptography/03-public-key-encryption-and-signatures.md))
- Using textbook RSA ($m^e \bmod n$ with no padding) outside a class exercise. It is deterministic and malleable. Use OAEP for encryption and PSS (or PKCS#1 v1.5 signatures where a protocol demands them) for signing. ([RSA step by step](../12-security/02-cryptography/04-rsa-step-by-step.md))
- Choosing key sizes below 2048 bits, or writing your own prime generation. Use a library to generate keys. ([RSA step by step](../12-security/02-cryptography/04-rsa-step-by-step.md))
- Encrypting a long message directly with RSA. The message must be shorter than the modulus. Encrypt a symmetric key and use AES-GCM for the data. ([RSA step by step](../12-security/02-cryptography/04-rsa-step-by-step.md))
- Turning off certificate verification (`verify=False`, `curl -k`, `NODE_TLS_REJECT_UNAUTHORIZED=0`) to make an error go away. The connection is then encrypted, but to anyone, including an attacker in the middle. Fix the chain or the trust store instead. ([The TLS handshake](../12-security/02-cryptography/05-the-tls-handshake.md))
- Believing the padlock means the site is safe. It means the connection is encrypted to the named host, not that the host is honest. ([The TLS handshake](../12-security/02-cryptography/05-the-tls-handshake.md))
- Enabling 0-RTT on endpoints that change state, such as a payment `POST`. A replayed request would run twice. ([The TLS handshake](../12-security/02-cryptography/05-the-tls-handshake.md))
- Assuming encryption alone makes you compliant. Encrypting at rest is one safeguard (principle 7). Collection, consent, retention and breach handling still apply, and a key stored with the data protects nothing. ([Privacy and PIPEDA](../12-security/02-cryptography/06-privacy-and-pipeda.md))
- Copying production personal data into a test or staging database. Use synthetic or masked data. ([Privacy and PIPEDA](../12-security/02-cryptography/06-privacy-and-pipeda.md))
- Sending personal data to a third-party service (analytics, an AI API, error tracking) without checking the purpose and consent. The organization stays accountable for data it hands to a processor. ([Privacy and PIPEDA](../12-security/02-cryptography/06-privacy-and-pipeda.md))

## DevOps and cloud

- Treating a container as a small VM. Containers are meant to run one main process. Data written inside a container is lost when the container is removed (volumes, in [the next lessons](../13-devops-and-cloud/01-containers/03-volumes-networks-and-compose.md), fix this). ([VMs vs containers](../13-devops-and-cloud/01-containers/01-vms-vs-containers.md))
- Assuming containers are a security boundary equal to a VM. Running untrusted code needs extra isolation; do not run an unknown image as root with `--privileged`. ([VMs vs containers](../13-devops-and-cloud/01-containers/01-vms-vs-containers.md))
- Mixing up image and container. You build and share images. You run, stop and delete containers. ([VMs vs containers](../13-devops-and-cloud/01-containers/01-vms-vs-containers.md))
- The app listens on `127.0.0.1` inside the container. Published ports reach the container's network address, not its loopback, so `curl` from the host fails. Listen on `0.0.0.0`. ([Docker images and Dockerfiles](../13-devops-and-cloud/01-containers/02-docker-images-and-dockerfiles.md))
- Baking secrets into an image with `COPY.env.` or `ENV API_KEY=...`. Layers keep them forever and anyone who pulls the image can read them. Pass secrets at run time and list `.env` in `.dockerignore`. ([Docker images and Dockerfiles](../13-devops-and-cloud/01-containers/02-docker-images-and-dockerfiles.md))
- `FROM node:latest`. The tag moves, so a build next month can differ from today's. Pin a major version, or a digest. ([Docker images and Dockerfiles](../13-devops-and-cloud/01-containers/02-docker-images-and-dockerfiles.md))
- Using `localhost` as the database host inside a container. `localhost` there means the container itself. Use the service name (`db`). ([Volumes, networks and Compose](../13-devops-and-cloud/01-containers/03-volumes-networks-and-compose.md))
- `docker compose down -v` in a project whose volume holds data you want. It deletes the data with no confirmation. ([Volumes, networks and Compose](../13-devops-and-cloud/01-containers/03-volumes-networks-and-compose.md))
- Publishing the database port (`5432:5432`) on every interface. Anyone on your network can then try to connect. Leave it unpublished, or bind to the loopback address: `"127.0.0.1:5432:5432"`. ([Volumes, networks and Compose](../13-devops-and-cloud/01-containers/03-volumes-networks-and-compose.md))
- Deploying the `latest` tag. Kubernetes and servers cache images by tag, so an updated `latest` may not be pulled, and you cannot say what is running. Use a unique tag per build. ([Registries and Kubernetes basics](../13-devops-and-cloud/01-containers/04-registries-and-kubernetes-basics.md))
- Pushing an image that contains secrets, to a public repository. Check the repository's visibility on Docker Hub and GHCR; a leaked token in a layer must be revoked, not just deleted. ([Registries and Kubernetes basics](../13-devops-and-cloud/01-containers/04-registries-and-kubernetes-basics.md))
- A `docker push` that is denied or reports "requested access to the resource is denied". The image name lacks the registry or your account name, or you are not logged in. Re-run `docker tag` with the full name and `docker login`. ([Registries and Kubernetes basics](../13-devops-and-cloud/01-containers/04-registries-and-kubernetes-basics.md))
- Rebuilding per environment. A build for production that pulls newer dependency versions than the staging build tests something different. Build once and promote. ([CI/CD concepts](../13-devops-and-cloud/02-ci-cd/01-ci-cd-concepts.md))
- Ignoring a flaky test. A test that fails one run in ten teaches the team to click "re-run". Fix it or quarantine it, or real failures will be ignored too. ([CI/CD concepts](../13-devops-and-cloud/02-ci-cd/01-ci-cd-concepts.md))
- A green pipeline means the checks passed, not that the change is correct. Missing tests pass silently. ([CI/CD concepts](../13-devops-and-cloud/02-ci-cd/01-ci-cd-concepts.md))
- Tabs or wrong indentation in YAML. Spaces only, two per level. A misplaced `with:` silently becomes a different key. Run `actionlint` on the file before pushing. ([GitHub Actions](../13-devops-and-cloud/02-ci-cd/02-github-actions.md))
- Pinning an action to a floating tag from an unknown author, such as `someone/tool@main`. Code you did not review then runs with your secrets. Prefer actions from `actions/` or well-known publishers at a major version, and for anything sensitive pin a full commit hash. ([GitHub Actions](../13-devops-and-cloud/02-ci-cd/02-github-actions.md))
- Assuming files persist between jobs. Each job starts on a clean runner, so pass files with artifacts, as `build` and `deploy` do above. ([GitHub Actions](../13-devops-and-cloud/02-ci-cd/02-github-actions.md))
- A rollback plan that ignores the data. Rolling code back is easy. If v2 wrote rows v1 cannot read, or dropped a column, the rollback fails. Make schema changes backward compatible and test the rollback as well as the deploy. ([Deployment strategies](../13-devops-and-cloud/02-ci-cd/03-deployment-strategies.md))
- A health check that only returns 200. If `/health` never touches the database, a broken instance still takes traffic. Check what the service needs to do its job, but not so deeply that one slow dependency takes every instance out at once. ([Deployment strategies](../13-devops-and-cloud/02-ci-cd/03-deployment-strategies.md))
- Leaving flags in forever. Old flags multiply the code paths you must test. Remove a flag once the rollout is complete. ([Deployment strategies](../13-devops-and-cloud/02-ci-cd/03-deployment-strategies.md))
- Committing `terraform.tfstate` to Git. The state can contain secrets and passwords in plain text. Keep it in a remote backend with locking (an S3 bucket plus a lock, or Terraform's cloud service) and add `*.tfstate` to `.gitignore`. ([Infrastructure as code](../13-devops-and-cloud/02-ci-cd/04-infrastructure-as-code.md))
- Fixing a problem in the console "just this once". The next `apply` reverts it, or hides it as drift. Change the files instead. ([Infrastructure as code](../13-devops-and-cloud/02-ci-cd/04-infrastructure-as-code.md))
- Running `apply` without reading `plan`. A rename can look like "destroy the old, create the new", which deletes a database. ([Infrastructure as code](../13-devops-and-cloud/02-ci-cd/04-infrastructure-as-code.md))
- Picking a Region by habit. Tutorials default to `us-east-1`, and resources created there are invisible when the console is set to Montreal. Always check the Region selector, or set it in the CLI profile. ([Cloud models and regions](../13-devops-and-cloud/03-aws/01-cloud-models-and-regions.md))
- Reading "managed" as "secured for me". Under shared responsibility the provider secures the platform, but a public S3 bucket or an open SSH port is your configuration. ([Cloud models and regions](../13-devops-and-cloud/03-aws/01-cloud-models-and-regions.md))
- Working as the root user. It has no permission limits, so a leaked session or a typo has no safety net. Use it once to set up, then lock it away with MFA. ([AWS account, IAM and billing](../13-devops-and-cloud/03-aws/02-aws-account-iam-and-billing.md))
- A policy with `"Action": "*"` and `"Resource": "*"` because "it works". It grants full control, and AI assistants suggest it often. Start with the specific actions the error message names. ([AWS account, IAM and billing](../13-devops-and-cloud/03-aws/02-aws-account-iam-and-billing.md))
- Trusting the budget alert as a limit. It lags by hours. Delete what you create, every time. ([AWS account, IAM and billing](../13-devops-and-cloud/03-aws/02-aws-account-iam-and-billing.md))
- Opening SSH (port 22) to `0.0.0.0/0`. Bots scan the whole internet for it within minutes. Allow only your own IP as `/32`, or skip SSH and use Session Manager. ([EC2](../13-devops-and-cloud/03-aws/03-ec2.md))
- Stopping an instance and believing it is free. The EBS volume, and any Elastic IP, still bill. Terminate what you do not need. ([EC2](../13-devops-and-cloud/03-aws/03-ec2.md))
- Committing the `.pem` file or leaving it world-readable. Keep it out of git and run `chmod 400` on it. ([EC2](../13-devops-and-cloud/03-aws/03-ec2.md))
- Making a bucket public to share one file. Use a presigned URL, or CloudFront. Public buckets are a common source of leaked data, and a wildcard principal in a policy is the cause. ([S3](../13-devops-and-cloud/03-aws/04-s3.md))
- Deleting a versioned bucket with `aws s3 rb --force` and expecting it to be empty. Old versions and delete markers remain, and the bucket cannot be deleted until they are removed. The lab shows how. ([S3](../13-devops-and-cloud/03-aws/04-s3.md))
- Assuming folders exist. Renaming a "folder" means copying every object to a new key and deleting the old one. ([S3](../13-devops-and-cloud/03-aws/04-s3.md))
- Setting Publicly accessible to yes, or allowing 5432 from `0.0.0.0/0`, "to test from my laptop". Bots find open database ports quickly. Connect from a server in the VPC, or through an SSH tunnel to one. ([RDS managed Postgres](../13-devops-and-cloud/03-aws/05-rds-managed-postgres.md))
- Deleting the instance and keeping the bill. A manual snapshot, a read replica or a final snapshot keeps costing until you delete it. A stopped RDS instance also restarts itself after seven days and still bills for storage (check [stopping an instance](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_StopInstance.html) for the current rule). ([RDS managed Postgres](../13-devops-and-cloud/03-aws/05-rds-managed-postgres.md))
- Treating Multi-AZ as a backup. It copies mistakes instantly; a `DROP TABLE` is dropped on the standby too. Backups and point-in-time restore cover that. ([RDS managed Postgres](../13-devops-and-cloud/03-aws/05-rds-managed-postgres.md))
- Overlapping CIDR blocks. Two VPCs that both use `10.0.0.0/16` cannot be connected later. Pick distinct ranges per environment from the start. ([VPCs and security groups](../13-devops-and-cloud/03-aws/06-vpcs-and-security-groups.md))
- Leaving a NAT gateway running after a lab. It bills hourly and per GB even with no traffic. The same goes for an Elastic IP that is not attached to anything. ([VPCs and security groups](../13-devops-and-cloud/03-aws/06-vpcs-and-security-groups.md))
- Putting a database in a public subnet "for convenience". A subnet is public because of its route table, so a missing or wrong route can silently expose it. Put databases in private subnets and keep Publicly accessible off. ([VPCs and security groups](../13-devops-and-cloud/03-aws/06-vpcs-and-security-groups.md))
- A public function URL (auth type `NONE`) lets anyone on the internet run your code at your expense. Use `AWS_IAM` or put API Gateway with authorization in front of anything real, set a reserved concurrency limit, and delete lab URLs when finished. ([Lambda and serverless](../13-devops-and-cloud/03-aws/07-lambda-and-serverless.md))
- Relying on a database connection or global variable surviving. Environments come and go, and many run in parallel, so a busy function can open hundreds of database connections at once. Put a pooler such as RDS Proxy between Lambda and Postgres. ([Lambda and serverless](../13-devops-and-cloud/03-aws/07-lambda-and-serverless.md))
- Infinite loops through triggers, such as a function that writes to the same S3 bucket that triggers it. Write results to a different bucket or prefix. ([Lambda and serverless](../13-devops-and-cloud/03-aws/07-lambda-and-serverless.md))
- Running the app as root, or on port 80 directly. Run it as a dedicated user on a high port and let nginx take the privileged ports. ([Deploying an app to EC2](../13-devops-and-cloud/03-aws/08-deploying-an-app-to-ec2.md))
- Opening port 3000 in the security group "to test". The app should be reachable only through nginx. Test with `curl localhost:3000` on the server. ([Deploying an app to EC2](../13-devops-and-cloud/03-aws/08-deploying-an-app-to-ec2.md))
- Asking for certificates repeatedly while debugging. Let's Encrypt limits failures and duplicates; fix DNS and the security group first, and use certbot's `--dry-run` or staging option to practise. ([Deploying an app to EC2](../13-devops-and-cloud/03-aws/08-deploying-an-app-to-ec2.md))
- Logging whole request bodies or headers "for debugging". They contain passwords, tokens and personal data, and log storage is rarely locked down. Log chosen fields, and redact the rest. ([Logging metrics and monitoring](../13-devops-and-cloud/04-operations/01-logging-metrics-and-monitoring.md))
- Alerting on the average. One slow user in a hundred does not move a mean, so use p95 or p99 and the error rate. ([Logging metrics and monitoring](../13-devops-and-cloud/04-operations/01-logging-metrics-and-monitoring.md))
- A metric label with unbounded values, such as a user ID or a full URL. Every distinct value creates a new time series and overloads the metrics store. Use route names and status classes. ([Logging metrics and monitoring](../13-devops-and-cloud/04-operations/01-logging-metrics-and-monitoring.md))
- Hunting for the root cause while customers are still failing. Roll back or switch the feature off first, then investigate. ([Incidents and on-call](../13-devops-and-cloud/04-operations/02-incidents-and-on-call.md))
- Changing things in parallel. Two people restarting services and editing config make the cause impossible to read afterwards. Route changes through the ops lead and write each one in the incident channel. ([Incidents and on-call](../13-devops-and-cloud/04-operations/02-incidents-and-on-call.md))
- A postmortem that ends with "be more careful". Pick an action that changes the system, such as a check in the pipeline, an alert or a runbook step. ([Incidents and on-call](../13-devops-and-cloud/04-operations/02-incidents-and-on-call.md))

## Software and system design

- Comments that restate the code (`# loop over items`). They go stale when the code changes and then lie. Write the reason, or delete the comment. ([Clean code](../14-software-and-system-design/01-software-design/01-clean-code.md))
- Abstracting too early. A `process(data, mode, flag1, flag2)` function that serves four callers is harder to read than four short copies. Wait for the third repeat. ([Clean code](../14-software-and-system-design/01-software-design/01-clean-code.md))
- Renaming for its own sake in a shared codebase. Follow the existing style; a consistent codebase is more readable than a perfect one that nobody can predict. ([Clean code](../14-software-and-system-design/01-software-design/01-clean-code.md))
- Reading SRP as "one method per class". The rule is one reason to change, so a class with ten methods about the same concern is fine. ([SOLID principles](../14-software-and-system-design/01-software-design/02-solid-principles.md))
- Inheritance for code reuse, which is where LSP breaks. If the subclass is not a true is-a, use composition. ([SOLID principles](../14-software-and-system-design/01-software-design/02-solid-principles.md))
- An interface with a single implementation and no test double. It adds a file and a name and removes no coupling. ([SOLID principles](../14-software-and-system-design/01-software-design/02-solid-principles.md))
- Starting from the pattern. Find the problem first (a long `if` chain, a hard-wired dependency), then pick a pattern if one fits. ([Design patterns](../14-software-and-system-design/01-software-design/03-design-patterns.md))
- Confusing a Python decorator (`@timed`) with the decorator pattern. They overlap, but the pattern also applies to classes that wrap other objects. ([Design patterns](../14-software-and-system-design/01-software-design/03-design-patterns.md))
- A "factory" or "manager" class that only calls one constructor. A plain function or the constructor itself is enough. ([Design patterns](../14-software-and-system-design/01-software-design/03-design-patterns.md))
- The "fat controller", where the route handler holds the business rules. They then cannot be reused from a script or a queue worker. Move them into a service. ([Layered architecture and MVC](../14-software-and-system-design/01-software-design/04-layered-architecture-and-mvc.md))
- Validating only in the browser. Anyone can send a request without your front end, so the server must check every input. ([Layered architecture and MVC](../14-software-and-system-design/01-software-design/04-layered-architecture-and-mvc.md))
- Layers that leak. If the business layer returns a database row object or raises an HTTP error, the layers are tangled and the boundary is only a folder name. ([Layered architecture and MVC](../14-software-and-system-design/01-software-design/04-layered-architecture-and-mvc.md))
- Starting with microservices for a product with a handful of developers. The overhead arrives on day one, while the problems they solve (team size, scale) do not. ([Monoliths and microservices](../14-software-and-system-design/01-software-design/05-monoliths-and-microservices.md))
- Services that share a database. Every schema change is then a cross-team change, and the "independence" is gone. ([Monoliths and microservices](../14-software-and-system-design/01-software-design/05-monoliths-and-microservices.md))
- Splitting along technical layers, or so finely that one user action calls twelve services. ([Monoliths and microservices](../14-software-and-system-design/01-software-design/05-monoliths-and-microservices.md))
- Refactoring without tests, then discovering a changed edge case in production. Write the characterization test first. ([Coupling, cohesion and refactoring](../14-software-and-system-design/01-software-design/06-coupling-cohesion-and-refactoring.md))
- Mixing a refactor with a behaviour change in one commit. A reviewer cannot tell which lines change behaviour. ([Coupling, cohesion and refactoring](../14-software-and-system-design/01-software-design/06-coupling-cohesion-and-refactoring.md))
- Refactoring code nobody needs to change. Improve what you are about to modify; leave stable code alone. ([Coupling, cohesion and refactoring](../14-software-and-system-design/01-software-design/06-coupling-cohesion-and-refactoring.md))
- Scaling before measuring. Adding servers to a system limited by one database query multiplies the cost and not the speed. Find the full resource first. ([Scalability basics](../14-software-and-system-design/02-system-design/01-scalability-basics.md))
- Stateful "stateless" servers. Sessions in process memory work with one server. With two, a user logs in on server 1 and is logged out on server 2. Move the state to a shared store. ([Scalability basics](../14-software-and-system-design/02-system-design/01-scalability-basics.md))
- Averages. An average of 100 ms can hide 5% of requests taking 3 seconds. Look at the 95th and 99th percentile. ([Scalability basics](../14-software-and-system-design/02-system-design/01-scalability-basics.md))
- A health check that always says "ok". If `/health` returns 200 without touching the database, the balancer keeps sending traffic to a server that cannot serve it. Check the dependencies the server needs, but keep the check fast. ([Load balancing](../14-software-and-system-design/02-system-design/02-load-balancing.md))
- Using `hash % n` for a cache pool. Adding one server invalidates most of the cache at once. Use consistent hashing. ([Load balancing](../14-software-and-system-design/02-system-design/02-load-balancing.md))
- Leaving the balancer as the single point of failure. Run at least two, or use a managed one. ([Load balancing](../14-software-and-system-design/02-system-design/02-load-balancing.md))
- A cache key that leaves something out. Caching `price:42` when the price depends on the user's country shows one user another's price. Put every input in the key (`price:42:CA`). ([Caching strategies](../14-software-and-system-design/02-system-design/03-caching-strategies.md))
- Caching without a TTL. A missed invalidation then serves wrong data forever. Always set a TTL, even a long one. ([Caching strategies](../14-software-and-system-design/02-system-design/03-caching-strategies.md))
- Write-behind for data you cannot lose. A crash between the cache write and the database save loses it. Use write-through for orders and payments. ([Caching strategies](../14-software-and-system-design/02-system-design/03-caching-strategies.md))
- Sending a read straight after a write to a replica. The read may not see the write yet. Read from the primary for that case. ([Database scaling: replication and sharding](../14-software-and-system-design/02-system-design/04-database-scaling-replication-and-sharding.md))
- Choosing a shard key that grows over time, such as a timestamp or an auto-increment id. New rows all go to the last shard. ([Database scaling: replication and sharding](../14-software-and-system-design/02-system-design/04-database-scaling-replication-and-sharding.md))
- Sharding early. It makes joins, transactions and migrations harder for years. Most systems never need it. ([Database scaling: replication and sharding](../14-software-and-system-design/02-system-design/04-database-scaling-replication-and-sharding.md))
- "CAP says pick two". Partitions are not optional. The choice that matters is consistency or availability while one is happening. ([CAP and consistency](../14-software-and-system-design/02-system-design/05-cap-and-consistency.md))
- Calling a system "consistent" without saying which kind. ACID consistency (constraints hold) is a different idea from CAP consistency (all nodes agree on the latest write). ([CAP and consistency](../14-software-and-system-design/02-system-design/05-cap-and-consistency.md))
- Retrying a non-idempotent write. A timeout does not tell you whether the write happened, and a retry may charge a card twice. Use an idempotency key. ([CAP and consistency](../14-software-and-system-design/02-system-design/05-cap-and-consistency.md))
- Assuming exactly-once. A consumer that adds money or sends an email on each delivery will do it twice. Deduplicate by message id. ([Queues and event-driven design](../14-software-and-system-design/02-system-design/06-queues-and-event-driven-design.md))
- Retrying forever. A bad message that always fails blocks the queue or loops. Cap the retries, back off between them, and send the message to a DLQ. ([Queues and event-driven design](../14-software-and-system-design/02-system-design/06-queues-and-event-driven-design.md))
- A queue with no monitoring. Depth, oldest message age and DLQ size are the first signs of trouble. ([Queues and event-driven design](../14-software-and-system-design/02-system-design/06-queues-and-event-driven-design.md))
- Limiting by IP alone. Users behind one NAT share a limit, and an attacker with many IPs has no limit. Use the user or API key once known, and IP only for unauthenticated routes. ([Rate limiting and API gateways](../14-software-and-system-design/02-system-design/07-rate-limiting-and-api-gateways.md))
- A limit counted in each server's memory. Behind a load balancer the real limit is multiplied by the number of servers. Count in a shared store. ([Rate limiting and API gateways](../14-software-and-system-design/02-system-design/07-rate-limiting-and-api-gateways.md))
- A `429` with no `Retry-After`. Clients then retry at once, which makes the overload worse. ([Rate limiting and API gateways](../14-software-and-system-design/02-system-design/07-rate-limiting-and-api-gateways.md))
- Mixing bits and bytes, or MB and Mb. Network speeds are in bits per second; storage is in bytes. Multiply by 8 to go from bytes to bits. ([Back-of-the-envelope estimates](../14-software-and-system-design/02-system-design/08-back-of-the-envelope-estimates.md))
- Using the average where the peak decides. A system sized for 11k QPS fails at 35k. ([Back-of-the-envelope estimates](../14-software-and-system-design/02-system-design/08-back-of-the-envelope-estimates.md))
- False precision. "18.2 TB" is an answer; "18.247 TB" claims accuracy the assumptions do not have. Say "about 20 TB". ([Back-of-the-envelope estimates](../14-software-and-system-design/02-system-design/08-back-of-the-envelope-estimates.md))
- Jumping to the design. Skipping steps 1 and 2 means you solve a problem nobody asked for. ([System design interviews](../14-software-and-system-design/02-system-design/09-system-design-interviews.md))
- Listing every technology you know. Add a component only when a number or a requirement asks for it, and say which. ([System design interviews](../14-software-and-system-design/02-system-design/09-system-design-interviews.md))
- Staying silent while thinking, or never stating a trade-off. The interviewer can only grade what they hear. ([System design interviews](../14-software-and-system-design/02-system-design/09-system-design-interviews.md))
- Hashing without a collision check. Two long URLs silently share a code, and one of them redirects to the wrong place. ([Case study: a URL shortener](../14-software-and-system-design/02-system-design/10-case-study-url-shortener.md))
- Counting clicks inside the redirect request. A slow analytics write makes every redirect slow. Send an event to a queue. ([Case study: a URL shortener](../14-software-and-system-design/02-system-design/10-case-study-url-shortener.md))
- Using sequential codes for private links. Anyone can walk through `4c92`, `4c93`, and read what others shortened. ([Case study: a URL shortener](../14-software-and-system-design/02-system-design/10-case-study-url-shortener.md))
- Ordering by the sender's timestamp. Phone clocks differ, so messages appear out of order. Use a server-assigned sequence per conversation. ([Case study: a chat app](../14-software-and-system-design/02-system-design/11-case-study-chat-app.md))
- Keeping the user to connection mapping inside each server. Another server cannot find the user. Keep it in a shared store. ([Case study: a chat app](../14-software-and-system-design/02-system-design/11-case-study-chat-app.md))
- Broadcasting presence to everyone. With millions of users, each status change becomes millions of messages. ([Case study: a chat app](../14-software-and-system-design/02-system-design/11-case-study-chat-app.md))

## AI and LLMs

- Thinking the model learns from your conversation. During inference the parameters are fixed. A chat "remembers" earlier turns only because the whole conversation is sent back as input each time. A new chat starts blank. ([From ML to transformers](../15-ai-and-llms/01-how-llms-work/01-from-ml-to-transformers.md))
- Thinking the model looks answers up. It generates the likeliest continuation. When that continuation is a fact, it is because the pattern was common in training, not because it was retrieved and checked. ([From ML to transformers](../15-ai-and-llms/01-how-llms-work/01-from-ml-to-transformers.md))
- Reading "next-token predictor" as "simple". The task is simple to state, but predicting the next token of a proof or a program well requires the model to have learned a lot about proofs and programs. ([From ML to transformers](../15-ai-and-llms/01-how-llms-work/01-from-ml-to-transformers.md))
- Counting words or characters instead of tokens. Use the provider's token counter (Anthropic documents a [token counting API](https://platform.claude.com/docs/en/build-with-claude/token-counting)) for real numbers; a library for another model family gives only an estimate. ([Tokens, embeddings and context windows](../15-ai-and-llms/01-how-llms-work/02-tokens-embeddings-and-context-windows.md))
- Asking a model to count letters or do digit-level work. It sees tokens, not letters, so "how many r's in strawberry" is harder than it looks. Ask it to write code that counts. ([Tokens, embeddings and context windows](../15-ai-and-llms/01-how-llms-work/02-tokens-embeddings-and-context-windows.md))
- Filling the window to be safe. Dumping a whole repository in can bury the lines that matter and raise cost. Send the relevant files. ([Tokens, embeddings and context windows](../15-ai-and-llms/01-how-llms-work/02-tokens-embeddings-and-context-windows.md))
- Assuming fine-tuning is how you teach a model your company's documents. It mostly changes style and format, and facts learned this way are unreliable. To give a model your data, put it in the prompt or retrieve it at request time. ([Training, fine-tuning and RLHF](../15-ai-and-llms/01-how-llms-work/03-training-fine-tuning-and-rlhf.md))
- Treating a refusal as a statement about what is true or legal. It reflects trained caution and the provider's policy, and a rephrased request can flip the outcome either way. Do not rely on it as a security control. ([Training, fine-tuning and RLHF](../15-ai-and-llms/01-how-llms-work/03-training-fine-tuning-and-rlhf.md))
- Assuming the model knows the latest version of a tool. Paste the current docs or changelog into the prompt when the version is newer than the cutoff. ([Training, fine-tuning and RLHF](../15-ai-and-llms/01-how-llms-work/03-training-fine-tuning-and-rlhf.md))
- Setting temperature to 0 and trusting the answer. It makes the output repeatable, not correct. A wrong top token is still wrong. ([Sampling and hallucinations](../15-ai-and-llms/01-how-llms-work/04-sampling-and-hallucinations.md))
- Asking "are you sure?" as the only check. The model may reverse a correct answer or defend a wrong one. Check against a source or a run instead. ([Sampling and hallucinations](../15-ai-and-llms/01-how-llms-work/04-sampling-and-hallucinations.md))
- Trusting a citation because it has authors, a year and a DOI. All of these are easy to generate. Open the link or search the title. ([Sampling and hallucinations](../15-ai-and-llms/01-how-llms-work/04-sampling-and-hallucinations.md))
- Choosing by a leaderboard rank or by the most expensive tier. Neither says anything about your inputs. Run your own cases. ([Choosing a model](../15-ai-and-llms/01-how-llms-work/05-choosing-a-model.md))
- Hard-coding one model forever. Model IDs are retired on a schedule (Anthropic lists retirement dates on its [overview page](https://platform.claude.com/docs/en/about-claude/models/overview), as of 2026), and new tiers appear. Keep the model name in config and keep your tests so you can re-run them. ([Choosing a model](../15-ai-and-llms/01-how-llms-work/05-choosing-a-model.md))
- Ignoring output length. Output tokens cost more and add latency, so ask for short answers when you only need a label. ([Choosing a model](../15-ai-and-llms/01-how-llms-work/05-choosing-a-model.md))
- Putting the key in source code or a front-end bundle. Anyone who finds it spends your money. Keep it in an environment variable on a server, never commit `.env` files, and call the API from your back end, not from the browser. ([Calling an LLM API](../15-ai-and-llms/02-building-with-llms/01-calling-an-llm-api.md))
- Ignoring `stop_reason`. A reply cut off at `max_tokens` looks like a complete answer. Check for `end_turn`, and raise `max_tokens` or stream if it is `max_tokens`. ([Calling an LLM API](../15-ai-and-llms/02-building-with-llms/01-calling-an-llm-api.md))
- Assuming the model remembers. Each request must resend the earlier messages, and the bill grows with the history. ([Calling an LLM API](../15-ai-and-llms/02-building-with-llms/01-calling-an-llm-api.md))
- Changing a prompt, trying one input, and shipping. A prompt that fixes one case often breaks two others. Keep a list of test inputs and rerun all of them after every edit. ([Prompt and context engineering](../15-ai-and-llms/02-building-with-llms/02-prompt-and-context-engineering.md))
- Stuffing the window. Pasting a whole repository or every past message costs tokens and can bury the facts that matter. Retrieve or summarize what the task needs. ([Prompt and context engineering](../15-ai-and-llms/02-building-with-llms/02-prompt-and-context-engineering.md))
- A long list of NEVER and ALWAYS rules. Give the reason and one example instead; shouting rules makes newer models over-apply them. ([Prompt and context engineering](../15-ai-and-llms/02-building-with-llms/02-prompt-and-context-engineering.md))
- Giving the model a tool that can do anything, such as `run_sql(query)` or `run_shell(cmd)` with write access. A wrong guess or an injected instruction becomes a deleted table. Give narrow tools (`get_order_status(order_id)`), use a read-only database role, and require human approval for anything that writes, spends or sends. ([Tool use](../15-ai-and-llms/02-building-with-llms/03-tool-use.md))
- Trusting the arguments because the schema was in the prompt. The model usually follows it, not always. Validate on every call, and check permissions in your code (does this user own order 1182?), not in the prompt. ([Tool use](../15-ai-and-llms/02-building-with-llms/03-tool-use.md))
- Vague descriptions. "Gets data" gives the model nothing to choose with. State what the tool returns, when to use it, and its limits. ([Tool use](../15-ai-and-llms/02-building-with-llms/03-tool-use.md))
- Blaming the model for a retrieval failure. If the right chunk is not in the top k, no prompt fixes the answer. Log the retrieved chunks and measure retrieval apart from generation. ([RAG embeddings and pgvector](../15-ai-and-llms/02-building-with-llms/04-rag-embeddings-and-pgvector.md))
- Changing the embedding model without re-embedding. Vectors from different models, or different dimensions, are not comparable, and a dimension mismatch is an error. Store the model name with the data. ([RAG embeddings and pgvector](../15-ai-and-llms/02-building-with-llms/04-rag-embeddings-and-pgvector.md))
- Ignoring who may see what. If chunks come from documents with different access rights, filter by permission in the SQL `WHERE` clause (or with row-level security) before the prompt is built. ([RAG embeddings and pgvector](../15-ai-and-llms/02-building-with-llms/04-rag-embeddings-and-pgvector.md))
- Reaching for an agent when a workflow fits. If you can write the steps down ("extract, then classify, then store"), write them as code. It is cheaper, faster and easier to test. ([Agents and harnesses](../15-ai-and-llms/02-building-with-llms/05-agents-and-harnesses.md))
- No limits or no checks. An agent needs a step cap, a cost cap, and a way to verify its own work, such as running the tests. "Done" from the model is a claim, not a result. ([Agents and harnesses](../15-ai-and-llms/02-building-with-llms/05-agents-and-harnesses.md))
- Broad permissions by default. An agent that can run any shell command with your credentials can delete files or leak secrets after one bad step or one injected instruction in a web page it read. Start with read-only access and add rights one at a time. ([Agents and harnesses](../15-ai-and-llms/02-building-with-llms/05-agents-and-harnesses.md))
- `print()` in a stdio server. It writes to stdout, which carries JSON-RPC, and breaks the connection. Use `logging` (stderr) instead. ([MCP (Model Context Protocol)](../15-ai-and-llms/02-building-with-llms/06-mcp.md))
- Installing a community server because its README looks good. It runs as you and its tool descriptions go into your model's context. Check the publisher, read the code for anything that touches files, shell or network, and pin the version. ([MCP (Model Context Protocol)](../15-ai-and-llms/02-building-with-llms/06-mcp.md))
- A tool with too much reach, such as `run_sql(query)` with a write-capable login. Offer narrow tools backed by a read-only account. ([MCP (Model Context Protocol)](../15-ai-and-llms/02-building-with-llms/06-mcp.md))
- Tuning the prompt on the same cases you score it on. The score goes up and tells you nothing about new inputs. Keep a held-out set that you look at only to confirm a change. ([Evals](../15-ai-and-llms/02-building-with-llms/07-evals.md))
- Trusting a judge you never checked. Compare its scores with human labels on a sample, use a rubric with concrete criteria, and be suspicious when longer answers always score higher. ([Evals](../15-ai-and-llms/02-building-with-llms/07-evals.md))
- A set that is too clean. Real inputs have typos, empty fields, other languages and requests the system should refuse. Add the failures you see in production to the golden set. ([Evals](../15-ai-and-llms/02-building-with-llms/07-evals.md))
- A long `CLAUDE.md`. Rules get lost in the noise and the agent follows fewer of them. Prune it like code. ([Claude Code](../15-ai-and-llms/03-ai-assisted-development/01-claude-code.md))
- Using `CLAUDE.md` for a rule that must never be broken. It is advice. Use a hook or a `deny` permission rule. ([Claude Code](../15-ai-and-llms/03-ai-assisted-development/01-claude-code.md))
- `bypassPermissions` on your own laptop. It is meant for disposable containers and VMs. ([Claude Code](../15-ai-and-llms/03-ai-assisted-development/01-claude-code.md))
- Letting the agent write both the code and the tests, then trusting the green result. If the tests are wrong, passing proves nothing. Read the tests first. ([The plan, build, test, review workflow](../15-ai-and-llms/03-ai-assisted-development/02-plan-build-test-review-workflow.md))
- Continuing a long, tangled session. After two failed corrections, start fresh. ([The plan, build, test, review workflow](../15-ai-and-llms/03-ai-assisted-development/02-plan-build-test-review-workflow.md))
- Reviewing only the happy path from the prompt. Pick your own inputs, especially empty and boundary ones. ([Reviewing AI code](../15-ai-and-llms/03-ai-assisted-development/03-reviewing-ai-code.md))
- Accepting a green test run. Ask what the test would do if the code were wrong. ([Reviewing AI code](../15-ai-and-llms/03-ai-assisted-development/03-reviewing-ai-code.md))
- Asking the same session "is this correct?" and believing "yes". It tends to defend its own output. Run the code or use a fresh session. ([Reviewing AI code](../15-ai-and-llms/03-ai-assisted-development/03-reviewing-ai-code.md))
- Clicking "allow always" to stop the prompts. You have granted that command to every future injection too. Allow narrow patterns. ([AI security risks](../15-ai-and-llms/03-ai-assisted-development/04-ai-security-risks.md))
- Assuming the tool's own protections are enough. The docs say they reduce risk and do not remove it. ([AI security risks](../15-ai-and-llms/03-ai-assisted-development/04-ai-security-risks.md))
- Pasting real customer data, tokens or production logs into a chat to debug. Redact first. ([AI security risks](../15-ai-and-llms/03-ai-assisted-development/04-ai-security-risks.md))
- Picking a tool from a ranking or a social media thread. Try two on the same small task from your own repository. ([AI coding tools landscape](../15-ai-and-llms/03-ai-assisted-development/05-ai-coding-tools-landscape.md))
- Ignoring the data policy because the tool is "only a plugin". A plugin that reads your repo sends it somewhere. ([AI coding tools landscape](../15-ai-and-llms/03-ai-assisted-development/05-ai-coding-tools-landscape.md))
- App-builder code treated as finished. It still needs the review checklist, a dependency audit and a security pass. ([AI coding tools landscape](../15-ai-and-llms/03-ai-assisted-development/05-ai-coding-tools-landscape.md))

## The workplace

- Waiting silently. Being stuck for two days looks like no progress to the team; a question after 30 minutes costs one person five minutes. ([How software teams work](../16-the-workplace/01-how-software-teams-work.md))
- Asking the wrong role. Priorities go to the PM, technical direction to the tech lead, workload and career to your EM. Asking an engineer "should we build this?" gets an opinion, not a decision. ([How software teams work](../16-the-workplace/01-how-software-teams-work.md))
- Confusing a story point with a number of hours, or a sprint with a deadline for everything. A sprint is a timebox for a goal, and the team can end it with unfinished items that return to the backlog. ([Agile, Scrum and Kanban](../16-the-workplace/02-agile-scrum-and-kanban.md))
- Treating the stand-up as a status report to the manager. The Daily Scrum is for the Developers to plan the next day of work. ([Agile, Scrum and Kanban](../16-the-workplace/02-agile-scrum-and-kanban.md))
- Writing the solution as the ticket ("add an index on orders.user_id"). If the real problem is a slow page, say that and list the target time; the index may not be the fix. ([Tickets, estimates and planning](../16-the-workplace/03-tickets-estimates-and-planning.md))
- Quoting a single number under pressure. A single number is heard as a promise. Give the range and what would move it. ([Tickets, estimates and planning](../16-the-workplace/03-tickets-estimates-and-planning.md))
- A ticket with no way to test it. If you cannot write the acceptance criteria, you do not know the work yet; schedule a spike. ([Tickets, estimates and planning](../16-the-workplace/03-tickets-estimates-and-planning.md))
- A "drive-by" rewrite inside a bug fix. It makes the diff unreadable. Put cleanup in a separate PR. ([Code review etiquette](../16-the-workplace/04-code-review-etiquette.md))
- Approving to be nice. An approval says you read the change and would be comfortable owning it. ([Code review etiquette](../16-the-workplace/04-code-review-etiquette.md))
- Arguing taste in review. If a linter or a style guide can settle it, let the tool decide (see [linters and formatters](../04-developer-tools-and-workflow/03-code-quality/03-linters-formatters-and-type-checkers.md)). ([Code review etiquette](../16-the-workplace/04-code-review-etiquette.md))
- Writing the doc after the code is done. It then justifies the choice instead of testing it, and reviewers rightly feel it is too late to object. ([Design docs and writing](../16-the-workplace/05-design-docs-and-writing.md))
- Only one option. A doc with one option and no alternatives is an announcement. Include the option that you rejected and why. ([Design docs and writing](../16-the-workplace/05-design-docs-and-writing.md))
- A 20-page doc nobody reads. If it is long, add a five-line summary at the top and move detail into appendices. ([Design docs and writing](../16-the-workplace/05-design-docs-and-writing.md))
- The big rewrite. "Let's rewrite it cleanly" usually takes longer than expected and drops behaviours nobody remembered. Improve it in small steps instead. ([Working in a legacy codebase](../16-the-workplace/06-working-in-a-legacy-codebase.md))
- Removing code that "is never used". Check callers across repositories, scheduled jobs and logs before deleting; search is not proof. ([Working in a legacy codebase](../16-the-workplace/06-working-in-a-legacy-codebase.md))
- Mixing a fix with a reformat. A diff of 800 changed lines hides the 8 that matter. ([Working in a legacy codebase](../16-the-workplace/06-working-in-a-legacy-codebase.md))
- Assuming public on GitHub means free to use. Without a licence file, you do not have permission to copy the code. ([Open source and licences](../16-the-workplace/07-open-source-and-licences.md))
- Copying a snippet from Stack Overflow or an AI answer into company code without thought. An answer can reproduce code from a copyleft project; check the origin and your company's rules. ([Open source and licences](../16-the-workplace/07-open-source-and-licences.md))
- Opening a big, unrequested pull request. Ask in an issue first; a maintainer may not want the change. ([Open source and licences](../16-the-workplace/07-open-source-and-licences.md))
- Listing every technology you touched once. A skills section of 40 items lowers trust; list what you could discuss in an interview. ([Resume and portfolio](../16-the-workplace/08-resume-and-portfolio.md))
- Duties instead of results ("Responsible for testing"). Say what changed because of you. ([Resume and portfolio](../16-the-workplace/08-resume-and-portfolio.md))
- An AI-polished resume full of generic phrases. Recruiters see many; specific numbers and tool names stand out. ([Resume and portfolio](../16-the-workplace/08-resume-and-portfolio.md))
- Coding before you understand. Spend the first few minutes on questions and an example; fixing a wrong approach after 20 minutes of code is costly. ([Technical interviews](../16-the-workplace/09-technical-interviews.md))
- Silence. The interviewer cannot give credit for thoughts they cannot hear. ([Technical interviews](../16-the-workplace/09-technical-interviews.md))
- Saying "done" without running a test. Interviewers expect you to find your own bugs. ([Technical interviews](../16-the-workplace/09-technical-interviews.md))
- A story where everything went well and you learned nothing. Choose a real example and show what you would do differently. ([Behavioural interviews](../16-the-workplace/10-behavioural-interviews.md))
- Blaming others. Describe a disagreement by what each person wanted and how you resolved it. ([Behavioural interviews](../16-the-workplace/10-behavioural-interviews.md))
- Rambling past three minutes. Aim for two. Stop after the result and let them ask follow-ups. ([Behavioural interviews](../16-the-workplace/10-behavioural-interviews.md))
- Inventing or inflating details. Interviewers probe with follow-up questions, and the lie costs more than a modest story. ([Behavioural interviews](../16-the-workplace/10-behavioural-interviews.md))
